# Mosaic：悬浮任务窗拖动区域与紧凑布局优化

状态：0.9.0 已实施并完成本机自动化验证，2026-11-17；改前基线为 0.8.0。本次解决小窗顶部难以拖动、整张卡片留白过多的问题，不改变任务数据或完成状态语义。整个卡片减少空白，没有以扩大拖动范围为理由增加空标题栏。

## 1. 原因定位

文件：`src/Modules/FloatingWindows/Mosaic.FloatingWindows.Wpf/FloatingSurface.cs`，`FloatingSurface.Create`。

| 位置（当前基线） | 原因 |
| --- | --- |
| 81 行，frame 的 Padding=12、Margin=4 | 标题栏外存在可见顶部内边距；它属于容器而非拖动控件 |
| 84–94 行，bar / drag | 拖动标记是单独 TextBlock；标题栏和其余空白没有统一命中背景及拖动语义 |
| 103 行，drag.MouseLeftButtonDown | DragMove 只绑定在拖动标记，不能覆盖顶部、边线和其他空白 |
| 77 行，CanResizeWithGrip | 优化时还需检查原生边缘缩放命中，避免顶边被缩放抢走；当前并未建立统一的移动/缩放区域规则 |

源码可确认绑定范围不足；原生顶边缩放实际命中还需在桌面测试中核实，不将该可能性冒充已复现根因。

留白原因还包括 `FloatingScreen.NaturalHeight` 的固定最少 88 DIP 及测量后额外加 8 DIP，叠加 `FloatingSurface.Create` 的独立工具栏、6 DIP 行间距和双侧 12 DIP Padding。`TaskFloatingContentSession` 内部状态按钮/标题/反馈区的边距也要同批核对，不能只缩外框而留下内部空块。

## 2. 预期效果

```text
┌══════════════════════════════┐ ← 顶部已有留边支持拖动
│ ○ 任务标题          ▾ ↗ ◇ × │ ← 首行同时放内容与工具
│   未完成                     │
└──────────────────────────────┘ ← 底边、底角可缩放
展开后在下方接备注与时间，无额外空白标题行
```

- 小窗**可见的顶部边线与已有顶部留边**、首行非按钮空白支持移动；紧凑、展开模式规则一致。拖动命中区域独立于视觉高度，不添加一整行空白撑高卡片。
- 顶部的圆角区域仅在窗口实际可见轮廓内命中，不把外侧透明装饰区域或其他应用的区域当作拖动入口。
- 置顶、关闭、恢复主窗口按钮保留完整点击区域及外围布局空间，按在按钮上不启动移动。已禁用按钮所在区域也不变成拖动区。
- 任务标题的展开按钮、完成按钮、备注正文、链接、滚动条与重试按钮维持原用途。正文选择复制不移动窗口。
- 拖动区显示移动光标和“拖动窗口”提示；按钮维持按钮反馈，缩放边显示对应缩放光标，光标与命中判定来自同一规则。
- 不要求精确点中“⠿”；可将标记缩为低干扰提示或移入工具提示，不为它单独占一行。工具与标题共用首行，保留按钮操作空间。

### 2.1 整张卡片的留白约束

- 外框内边距默认从 12 收到 8 DIP；内容行间距默认 4 DIP，边距只应用一次，容器与任务内容不重复叠加。
- 紧凑模式取消独立空标题栏，任务标题/状态与右侧工具共享布局。正常单行标题目标约 64–76 DIP 总高度；双行标题、较大字体按实际需要增加，不为满足目标裁字。
- 自然高度只计算实际可见内容与一次边框/装饰尺寸，移除无内容依据的 88 DIP 下限及重复额外高度。最小尺寸仍须容纳按钮与系统可访问性要求，不把高度压到无法操作。
- 无错误、无重试、无备注时，对应占位区真正 Collapsed；不通过空 TextBlock、透明框或固定行高留出空块。
- 展开模式收紧标题、正文、时间之间的间距，短内容不在内部铺额外空白区；用户明确调整的窗口高度继续尊重，超长正文仍能滚动。
- 按钮可视图形可紧凑，点击区域不靠裁小按钮实现；最小宽度下允许标题合理换行，工具不重叠、不挤掉完成按钮。
- 首行共排通过容器布局与公开格式选项协调：浮窗模块只负责工具区域，Tasks UI 仍负责标题/状态/备注；不能为减少空白让容器读取任务字段。

## 3. 统一命中与拖动策略

按以下优先级判定一次输入的用途：

1. 工具按钮及其保留区域：按钮交互。
2. 可见顶部拖动带（包括顶边及顶部圆角可见部分）：移动。
3. 拖动带以外的左右边缘、底边和底部两角：缩放。
4. 任务内容：原有点击、选择与滚动。

顶部两角按移动处理，大小调整使用顶部拖动带以下的左右边及底边/底角。这样“最顶部可拖动”不会与同一位置的上边缘缩放产生冲突；窗口仍可调整大小。

实现要点：

- 将独立工具栏与内容合为紧凑首行，顶部既有留边包含在拖动带内；命中背景不额外撑高视觉布局，不能依靠文字字形命中。
- 在 Floating WPF 内抽取统一命中判定，根据真实控件边界和控件祖先判断，不按“右边固定 N 像素”排除按钮。语言、DPI、按钮尺寸变化后仍有效。
- 拖动入口从单一 TextBlock 上移至标题栏/容器的统一处理点，旧标记处理器撤销，避免同次输入触发两个 DragMove。
- 检查 WindowStyle=None、透明窗和现有原生消息钩子的关系；必要时同步调整原生命中，确保顶边不会先被判成缩放。原生命中与 WPF 入口共用区域策略，实际移动只走一条路径。
- 只响应左键；按下后使用系统移动流程保持抓取偏移。右键、中键、按钮操作均不启动移动；双击标题栏不额外最大化或展开任务。
- 移动期间继续使用已有 Moving 标志，暂停自动重排；松手后复用 QueueBounds / WM_EXITSIZEMOVE 的位置保存管线并合并重复通知，不另建坐标存储或队列。
- 取消/捕获丢失/窗口释放后清理拖动状态；窗口正在关闭或冻结时不启动拖动。跨屏仍用现有 DPI 与工作区转换，不允许标题栏永久移到屏幕外。

## 4. 模块归属与设置

窗口命中、移动、缩放和外框密度归 `Mosaic.FloatingWindows.Wpf`；任务内容内部布局仍归 Tasks UI，通过公开格式选项协作。Tasks UI 不接收“移动窗口”的内部对象，Core/Sqlite 不新增业务规则，Presence 的速览拖出手势不受此区域逻辑接管。

拟新增 3 个高级参数：`floating.dragBandHeight` 默认 12 DIP、范围 8–20 DIP，仅控制顶部命中带，不创建等高空白行；`floating.cardPadding` 默认 8 DIP、范围 4–16 DIP；`floating.contentGap` 默认 4 DIP、范围 0–12 DIP。撤销此前拟议的 `floating.headerHeight=36` 参数，避免把拖动区做成加高标题栏。

定义由 FloatingSettings 唯一注册到现有“悬浮任务窗”分组，采用 Immediate + Reversible 预览；密度变化只影响运行布局，不覆盖已保存的用户窗口尺寸。放弃预览恢复原值。设置总数现为 96 项（14 普通 / 82 高级）。

使用系统缩放边界和移动规则，不为每条边另造相互冲突的配置。旧配置缺少新值时使用默认值；数据库与窗口记录结构不变，无需表迁移。窗口保存位置继续沿用既有记录，老小窗在新版本恢复后应用新的命中布局。

## 6. 验收

- 最上方可见边线、顶部内边距、标记、标题栏中部空白，均可按住拖动；分别测试紧凑/展开及最小宽度。
- 在置顶、恢复、关闭按钮的中心/边缘、按钮内图形上按下只执行按钮动作，不移动窗口；禁用按钮亦不落入拖动。
- 完成按钮、任务标题展开、正文选字复制、滚轮、滚动条、重试均保持正常，不误拖。
- 顶边及顶部两角移动，侧边下部/底边/底角缩放；不存在同一次拖动既移动又缩放的情况。
- 只按下不移动、移出后松手、右键/中键、快速重复、关闭期间输入、跨屏抓取和取消均无残留捕获或异常。
- 100/125/150/200% DPI、跨 DPI、浅色/深色/高对比度、不同字体与语言、8/12/20 DIP 命中带与不同边距、工作区不足均测试按钮可达及区域一致。
- 0.8.0 改前/改后同宽截图对比：单行、双行、空备注、短/长备注、无错误状态；紧凑首行无独立空工具栏，空反馈区不占高度，边距不重复。不得为减少空白裁掉标题或缩小按钮点击范围。
- 拖后正常退出并重启，位置正确恢复；调整拖动带预览后放弃，不改持久化窗口偏好；保存失败仍有可重试反馈。

自动化以明确命中断言配合真实拖动/按钮路径验证；不能只检验事件处理器已经绑定。
