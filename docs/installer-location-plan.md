# Mosaic：安装位置选择、同程序替换与桌面快捷方式计划

状态：2026-11-20，基于 0.17.2 重新规划。桌面快捷方式子项已在 0.9.1 实施；自定义安装位置与同版本 MSI 文件扫描修复尚未实施。本次用户确认的交付范围、技术路径和验收以第 10 节为准；第 1–9 节保留历史设计与结果，其中跨位置替换及无登记目录覆盖不作为本次自动执行行为。

关联：[架构原则](architecture-principles.md)、[总实施计划](implementation-plan.md)、[实施与验证记录](implementation-status.md)。

## 1. 已确认需求与规划默认

用户要求：安装程序允许选择安装位置；目标位置存在同一程序时替换它；安装完成后自动在当前用户的桌面创建 Mosaic 快捷方式。

当前模式无法使用交互式选择题，因此本次按以下保守默认定稿，实施前如用户明确改变选择，再以同一交付单元修订：

- 继续保持**每用户安装**，不引入管理员权限或每机器安装。用户只能选择自己有写入权限的位置。
- 安装界面采用**位置输入框 + 浏览文件夹按钮 + 恢复默认**；不使用多页向导，也不只留一个不能编辑的按钮。
- 检测到 Mosaic 已安装在其他位置时，**显示实际安装位置和版本，要求确认后才替换**；不再静默改变安装位置。
- 目标目录已存在同名程序但没有 Windows Installer 产品登记时，显示冲突并允许继续覆盖该目录中的 Mosaic 程序文件；非 Mosaic 文件保留。
- 安装完成后自动创建当前用户桌面和开始菜单的 Mosaic 快捷方式，两者都指向最终 `INSTALLFOLDER`；不增加管理员权限，也不显示另一套桌面快捷方式开关。
- 同位置升级与跨位置替换完成后，桌面快捷方式必须存在且目标为新的当前位置；卸载删除本产品登记的桌面和开始菜单快捷方式，用户数据仍保留在 `%LOCALAPPDATA%\Mosaic`。

这里的“替换”指替换程序文件和 Windows Installer 登记。任务数据库、设置、日志、浮窗状态与备份文件都不在安装目录内，绝不随着替换删除。

## 2. 根因与职责边界

根因位置：

| 位置 | 当前事实与问题 |
| --- | --- |
| `build/installer/Package.wxs:7` | `LocalAppDataFolder/Programs/Mosaic` 把 `INSTALLFOLDER` 写死，MSI 没有位置选择界面。 |
| `build/installer/Package.wxs:2–3` | 使用固定 `UpgradeCode` 的 `MajorUpgrade`；已安装同产品时能够升级，但无法在用户选择新位置后可靠表达“从旧位置搬走”。 |
| `build/installer/Package.wxs:10` | 快捷方式引用 `INSTALLFOLDER`，本身正确；目录改造后无需第二套路径逻辑。 |
| `build/installer/Package.wxs:10-14` | 当前只为 `ProgramMenuFolder` 创建开始菜单快捷方式，`DesktopFolder` 没有受 MSI 组件管理，因此安装后不能保证自动创建桌面入口。 |
| `build/package.ps1:33–59` | 生成负载时以固定 `INSTALLFOLDER` 为根；没有记录安装位置元数据或冲突检测所需的产品信息。 |
| `build/test-install.ps1:28、38` | 烟雾和卸载断言写死 `%LOCALAPPDATA%\Programs\Mosaic`，无法验证自定义位置。 |

这不是业务模块职责：安装、目录选择、旧安装检测和卸载清理全部由安装器负责。应用模块继续只读取宿主注入的数据根目录，不得判断自己是否来自自定义安装位置，也不得安装或修改自己的快捷方式。`%LOCALAPPDATA%\Mosaic` 是非安装数据目录，不因安装位置变化而搬迁。

不新增应用内设置项；安装位置由 MSI 持久化，设置模块不展示、不编辑、不预览该值。

## 3. 安装状态模型

安装器只处理以下互斥结果：

1. `Fresh`：没有已登记 Mosaic，目标目录为空或没有 Mosaic 程序文件。按所选位置安装。
2. `RegisteredSameProduct`：检测到同一 `UpgradeCode` 的已安装 Mosaic。读取其 `INSTALLLOCATION`、版本和产品代码，显示“当前安装 → 目标安装”，确认后执行升级。
3. `RegisteredOtherProduct`：检测到同名但 `UpgradeCode` 不同的产品。拒绝安装并提示用户先卸载，避免把无关产品当作 Mosaic 覆盖。
4. `DirectoryConflict`：目标目录有 `Mosaic.Desktop.exe` 但没有可靠的 Mosaic 产品登记。提示目标路径，要求明确确认覆盖；只覆盖本安装包负载清单中的文件。
5. `InvalidTarget`：路径为空、相对路径、包含无效字符、指向根目录、不可写或权限不足。阻止进入下一步并给出具体原因。

同一位置重复安装同一个 MSI 也按状态 2 处理；安装器不得因“目标已存在”直接失败。

桌面快捷方式的创建与安装结果原子绑定：安装成功、修复或升级后应存在；安装取消、失败或回滚时不得留下指向临时目录或旧位置的半安装快捷方式。用户数据、任务数据库和设置不属于快捷方式组件，不随其删除。

## 4. 安装界面与路径规则

在 `Package.wxs` 中增加 WiX 标准 UI 与自定义位置页：

- 默认路径保持 `%LOCALAPPDATA%\Programs\Mosaic`，文本框显示可编辑的完整路径并带“恢复默认”按钮。
- 浏览文件夹对话框从当前输入位置开始；用户选择目录后，安装目录仍以该目录内的 `Mosaic` 命名，防止误选磁盘根目录后把程序散落到根下。例如选择 `D:\Apps` 得到 `D:\Apps\Mosaic`。
- 路径必须先验证再写入 `INSTALLFOLDER`：必须为绝对路径、不能是卷根、不能是系统关键目录、不能包含未解析的 `%...%` 占位符、必须以当前用户身份可写。只接受本地 NTFS/ReFS 路径，不接受 UNC 网络路径。
- 确认页显示最终目录、是全新安装还是替换、检测到的旧版本、用户数据保留说明。用户返回上一步时不修改任何文件或安装登记。
- 确认页同时说明安装完成后会在当前用户桌面创建 Mosaic 快捷方式；不提供独立的额外向导页，也不要求管理员权限。
- 输入框、浏览按钮、恢复默认、确认和取消都要有中文可访问名称；键盘 Tab 顺序明确，Esc 取消浏览对话框。
- 不显示系统托盘或后台驻留选项；那些功能属于应用设置。

界面改用 WiX 标准 UI 后，需要恢复 ICE 校验至现有项目允许的集合。当前仅因项目既有原因抑制 `ICE91`（每用户安装）和 `ICE60`（上游 SQLite 原生 DLL 语言资源）；新增位置页不得再新增全局抑制项。

## 5. 替换与卸载语义

保持现有 `<MajorUpgrade Schedule="afterInstallInitialize" />`，使 MSI 正常处理同产品升级。增加位置页后按以下规则执行：

- 检测到旧安装且确认替换：在同一事务中先移除旧 `UpgradeCode` 产品的程序文件和登记，再安装到新 `INSTALLFOLDER`；首次提交前失败则回滚到旧安装。
- 旧安装位置和新位置相同：执行普通就地升级，保留已存在且不属于负载清单的文件。
- 旧安装位置和新位置不同：删除旧位置的负载文件与空目录，创建新位置；不复制、不删除 `%LOCALAPPDATA%\Mosaic` 数据目录。
- 卸载：删除当前登记的 `INSTALLFOLDER` 负载、空目录、开始菜单项和本产品创建的桌面快捷方式；保留用户数据、数据库备份及其他位置的遗留文件。
- 回滚：若安装在新位置失败，旧产品登记与程序文件保持可用；若失败发生在首次安装，则删除本次创建的文件与空目录。
- 快捷方式：使用 `DesktopFolder` 下的独立 Windows Installer 组件创建 `Mosaic.lnk`，目标固定为 `[INSTALLFOLDER]Mosaic.Desktop.exe`、工作目录为 `INSTALLFOLDER`；跨位置安装时由 MSI 更新目标，不能在旧位置留下仍可启动的快捷方式。

自定义动作只做检测和属性设置，不复制业务文件、不读写任务数据库、不直接删除整棵用户选择的目录。所有文件删除由 Windows Installer 依据负载清单和组件规则完成，避免误删同目录下的其他内容。

目录冲突中的非 Mosaic 文件保持不动。只有在目录完全由本次安装创建且卸载后为空时，才由 `RemoveFolder` 删除目录本身。

## 6. 实施步骤与改动位置

按同一交付单元实施，禁止只改 MSI 而不更新测试和文档：

1. 在 `build/installer/Package.wxs` 增加 `WixUI`/位置页、产品检测属性、目标路径校验、确认页文案和当前位置检测；保留 `UpgradeCode`、每用户范围和启动条件。
2. 在 `build/package.ps1` 生成负载时加入安装器需要的产品元数据，继续排除 `Data`、`Config`、`Logs` 和运行锁文件；输出目录仍为 `artifacts/installer`。
3. 在 `build/installer/Package.wxs` 增加 `DesktopFolder` 下独立组件和 `Feature` 引用，创建当前用户桌面 `Mosaic.lnk`；快捷方式目标与工作目录使用最终 `INSTALLFOLDER`。MSI 组件负责升级更新和卸载删除，应用代码不自行创建快捷方式。
4. 新增安装器 UI/代理测试，覆盖默认路径、自定义路径、无效路径、旧安装地址读取、用户取消和桌面快捷方式组件；可用 WiX 编译期检查和 MSI 数据库回读验证属性，但不把静态检查冒充真实安装。
5. 修改 `build/test-install.ps1`：移除写死安装路径的断言，从 MSI 登记的 `INSTALLLOCATION` 读取实际位置；加入默认位置安装、自定义位置安装、同位置升级、跨位置替换、桌面快捷方式目标校验和卸载保留用户数据矩阵。
6. 更新 `docs/releases/` 下一版本发布说明、`build/release-content.json`、`build/release-manifest.json`、`build/published-release-index.json` 的“更新简要”，写明安装位置可选、自动桌面快捷方式、替换提示、数据保留和已有安装用户操作步骤。
7. 更新 `README.md` 的安装路径与桌面快捷方式说明、总计划新阶段和本实施记录；构建产物、测试与文档属于同一个版本。

不新增应用设置、迁移任务或业务模块。若将来改为每机器安装，需要重新审查 `Scope`、`UpgradeCode`、权限、ICE 和数据目录，不能直接把路径框改成 `Program Files`。

| 场景 | 期望结果 |
| --- | --- |
| 干净用户安装，使用默认位置 | 安装到 `%LOCALAPPDATA%\Programs\Mosaic`；桌面和开始菜单自动创建快捷方式且可启动；数据目录可创建 |

| 默认位置已有旧版 Mosaic | 显示旧版本/旧位置和新位置；确认后升级；取消则原安装完全不变 |
| 旧版在默认位置，新版选择自定义位置 | 确认后旧位置程序文件清除，新位置可运行；桌面快捷方式目标更新为新位置；用户数据哈希不变 |
| 自定义位置已有旧版 Mosaic | 同位置升级成功；桌面快捷方式保留并指向当前位置；负载外的哨兵文件保留 |

| 安装中途失败或取消 | 旧安装恢复或首次安装痕迹清除；不留临时或半安装桌面快捷方式 |
| 卸载自定义位置安装 | 程序文件、桌面快捷方式和开始菜单快捷方式消失；用户数据、数据库备份和负载外文件保留 |
| 桌面快捷方式属性 | 当前用户桌面存在 `Mosaic.lnk`，目标为最终 `INSTALLFOLDER\Mosaic.Desktop.exe`，工作目录为 `INSTALLFOLDER` |
| 桌面烟雾 | 默认与自定义位置均能创建任务、重开读取、设置保存、关闭后驻留 |
| 静态检查 | Release 构建 0 警告；ICE 除既有两项外无新增问题；MSI 数据库回读版本与 `INSTALLLOCATION` 正确 |

受限会话若无法访问 Windows Installer 服务，必须把 ICE 和真实安装场景记录为“待验收”，不得用 MSI 生成成功代替。交互安装应按普通用户权限执行，并记录安装日志路径。

## 8. 同步交付与完成定义

本变更完成需同时满足：

- MSI 可选择位置，且默认位置与现有安装兼容；安装成功后自动创建当前用户桌面快捷方式。
- 检测到同产品时给出确认，确认后能替换；取消或无权限时不产生半安装。
- 桌面与开始菜单快捷方式都指向最终安装位置，升级、跨位置替换和卸载行为一致；用户数据目录始终不受安装位置和快捷方式生命周期影响。
- 自动化、安装矩阵、发布内容源、更新简要任务、发布说明、README 与实施记录属于同一版本。
- 最终回复和实施记录写明根因位置与每个实际改动位置；未完成的真实安装/ICE 验收明确列出。

## 10. 2026-11-20 当前方案：可选安装位置与同版本 MSI 扫描修复

### 10.1 用户行为与交付范围

用户要求：安装时能选择安装位置；已安装成功后，再次使用同版本安装包，启动维护，扫描残缺文件并修复。

本节已于 0.17.3 实施并随同一提交交付（源码、安装包、静态校验与发布）；真实安装、破坏与升级矩阵尚未在隔离环境执行，状态见 §10.9。沿用单个离线 MSI、每用户安装和固定 UpgradeCode；安装器承担文件维护职责。

| 状态 | 安装包打开后的行为 |
| --- | --- |
| 未安装 | 显示安装位置输入框、浏览和恢复默认；确认最终目录后安装 |
| 已安装同一正式版本与对应产品身份 | 自动进入「检查与修复」，显示已安装版本和实际位置；扫描后健康则提示无需修复，异常则自动修复并显示结果 |
| 已安装较旧版本 | 进入升级，显示原版本及原位置，默认原位升级并继承原路径 |
| 已安装较新版本 | 提示已有新版，阻止降级 |
| 只有同名目录/EXE，没有可靠产品登记 | 显示目录冲突，要求选择其他目录；避免把无登记文件当作已安装产品 |
| 安装登记或路径无法可靠识别、文件不可读 | 报告检查失败与具体原因；不得把无法检查显示成健康 |

同版本维护固定使用原安装位置；重新选择安装位置只出现在首次安装。已有安装需要换位置时，明确引导先卸载程序（保留数据），再安装到新位置。本次以原位升级保障已有自定义路径；历史计划中的跨位置替换另行设计事务与回滚。

健康状态表示不执行文件重装、不改快捷方式、不退出当前应用、不启动新实例；扫描读取、必要的安装器临时文件与诊断日志允许存在。

### 10.2 当前根因与能力缺口

- `build/installer/Package.wxs:7`：INSTALLFOLDER 的默认目录写在 `LocalAppDataFolder/Programs/Mosaic` 下，没有目录选择 UI，故交互安装无法更改位置。
- `build/installer/Mosaic.Installer.wixproj:1–13`：只引用 WiX SDK 与 Payload，没有 UI 扩展和维护流程装配。
- `build/installer/Package.wxs:2–4`、`:27`：已有 MajorUpgrade 和 Application Feature，但没有同版本「扫描 → 判断 → 修复 → 复检」调度；默认 Windows Installer 行为不等于本需求。
- `build/package.ps1:69–78` 与 `scripts/package_payload.py:106–116`：逐文件组件以 HKCU 注册表值作为 KeyPath，文件本身是 `KeyPath="no"`。即使 DLL 被删除，组件的登记标记仍可存在；仅靠组件状态不能证明所有程序文件完整。
- 两条负载生成链都没有为维护提供逐文件大小、SHA-256 与相对路径清单。普通按版本重装规则也不能证明同大小、同版本号的损坏二进制会被替换。
- `Package.wxs` 没有设置 `ARPINSTALLLOCATION` 或独立、可供后续版本读取的安装路径登记；`WindowsMaintenanceService.FindInHive`（`src/Modules/Maintenance/Mosaic.Maintenance.Windows/WindowsMaintenanceService.cs:120–136`）读取 InstallLocation 可能得到 null。可选目录后需要可靠回读真实位置。
- `build/test-install.ps1:57`、`:62`、`:66`、`:73` 的断言固定使用默认目录，无法证明自定义目录与维护修复正确。
- 应用内「检查并修复」检查的是配置（`MaintenanceViewModel.RepairAsync` / `DesktopConfigurationHealthCheck`）。它无法在 EXE 或运行时 DLL 缺失时启动，不能替代 MSI 文件维护验收。

### 10.3 首次安装：位置选择与登记

1. 增加 WiX v4 对应版本的 UI 扩展，并用精简的中文位置页提供完整路径输入、浏览、恢复默认、安装和取消。默认仍为 `%LOCALAPPDATA%\Programs\Mosaic`。
2. 输入框显示最终安装目录；浏览选择的是父文件夹时追加 `Mosaic` 并立即回显最终路径，已选文件夹本身名为 Mosaic 时不重复追加。确认页和所有日志使用同一个规范化后的 INSTALLFOLDER。
3. 路径支持空格、中文与可写的本地固定磁盘目录。验证绝对路径、实际卷与权限、可用空间、目录冲突；拒绝卷根、网络路径、系统目录、用户数据目录及其父子冲突，以及可能使安装文件落入用户数据树的链接路径。主程序文件不能安装到数据库、配置或凭据目录内。
4. 保持 per-user 权限；选择当前用户无写权限的目录时回显错误并允许重新选择。
5. 安装事务成功后设置 `ARPINSTALLLOCATION=[INSTALLFOLDER]`，并在产品拥有的 HKCU 组件中持久化实际路径；只有事务提交后该路径才成为下一次维护的依据。
6. 桌面、开始菜单快捷方式继续绑定 INSTALLFOLDER，工作目录一致；后续原位升级、修复、卸载均从产品登记读取位置。
7. 静默安装支持标准 INSTALLFOLDER 属性，走同等路径验证；无人值守场景不弹浏览框、不自动启动桌面应用。
8. 数据根仍由 `AppPaths.FromArguments`（`src/Mosaic.Desktop/AppConfiguration.cs:485–489`）决定，默认 `%LOCALAPPDATA%\Mosaic`；已有数据库迁移目标也保持原值。

### 10.4 同版本维护：可靠扫描

采用 MSI 内嵌的原生自定义动作 DLL 完成身份检测、只读扫描与结果归类，使用 Win32/Windows Installer API、BCrypt SHA-256，静态链接运行库。扫描器随 MSI 自身提供，能够在安装目录整个丢失、EXE 或 .NET 运行时损坏时独立运行。业务应用不参与扫描。

- 发布时从最终、已验证的载荷生成不可变清单：相对路径、文件大小、SHA-256、对应 File/Component ID；清单嵌入 MSI 的 Binary 资源，由本次安装包读取。不得信任安装目录里可被改写的清单作为校验基准。
- 清单覆盖 EXE、DLL、运行时文件、语言资源及其他 MSI 拥有的静态文件；排除 Data、Config、Logs、凭据、备份、锁文件、目标目录内用户另放的文件。安装目录的默认 `appsettings.json` 作为静态模板可校验；用户 Config/appsettings.json 不属于扫描修复对象。
- 清单生成和 Payload 生成使用同一份文件选择规则；打包同时断言清单与 File 表一一对应，防止 Python 与 PowerShell 两条链漏收文件。
- 身份通过 UpgradeCode、ProductCode、版本及当前用户安装上下文确定；DisplayName 与 EXE 存在只能辅助展示。对同一正式版本保持不可变发布产物；同版本不同产品身份或载荷的重打包不能静默视为同一安装。
- 位置优先从 Windows Installer 登记及本产品安装路径元数据读取。0.17.2 及以前未记录位置的产品，只能在身份已确认后使用其固定默认位置兼容兜底；新式自定义安装位置丢失时应报错，不按默认目录另建副本。
- 逐项分类：缺失、大小不符、大小相同但哈希不符、无法读取。大小相同仍需哈希校验；无法读取必须作为检查错误，不能作为健康或直接覆盖的理由。
- 检查 MSI 拥有的桌面/开始菜单快捷方式是否缺失、目标或工作目录错误；异常也触发维护恢复。
- 目标路径按句柄/规范化实际路径验证，防止文件或中间目录的重解析点令扫描和修复落到安装根之外。无法确认边界时停止并给出错误。
- 扫描只读，可取消；显示检查进度及「缺失 X 项、损坏 Y 项」摘要。它是安装完整性检查，不能把同一时刻的哈希检查宣称为对恶意并发替换的完整防护。

### 10.5 修复执行、复检与失败行为

- UI 顺序：进入维护 → 自动扫描 → 健康则显示「安装完整，无需修复」；有可修复项则显示摘要并自动进入 MSI 修复 → 复检 → 显示完成或失败。
- 文件恢复由当前 MSI 的 Windows Installer 事务执行，不由自定义动作直接复制/删除程序文件；避免在运行中的 MSI 会话内递归调用另一条 msiexec 命令。
- 初始选择 `REINSTALL=ALL` 与 `REINSTALLMODE=amus`（等价于强制重装受管文件并恢复每用户登记、必要登记及快捷方式）的维护路径：扫描健康时完全跳过；扫描异常时允许恢复整套 MSI 受管载荷，确保有版本号的损坏 DLL 和同大小损坏文件都会恢复。首版不以「只替换坏文件」增加组件调度复杂度。
- 现有逐文件 HKCU KeyPath 与组件 GUID 在本次保持兼容；不能为了检测缺失而把既有组件随意改成文件 KeyPath。完整性由显式清单扫描判断，修复参数必须用真实损坏实验验证。
- 通过 Restart Manager / FilesInUse 处理正在运行的 Mosaic。真正需要替换文件时才提示保存并关闭；用户取消关闭则停止修复并保留原安装，不直接强杀应用。健康扫描不要求退出。
- 以原 MSI 的 CAB 为恢复来源，整套离线完成；源不可读或 Windows Installer 缓存/源丢失时明确要求原版本安装包，不能报成功。
- 正确传播标准 MSI 成功、取消、失败及需重启返回码（包含 3010）。文件被安排到重启后替换时显示「需重启后完成修复」，不能把重启前哈希仍不匹配报为修复成功。
- 修复后重新对照包内清单验证；只有受管文件与必要快捷方式均恢复才显示成功。复检失败进入错误页与诊断日志；成功提交后的复检失败不宣称 MSI 自动回滚，事务内部失败才遵循 Windows Installer 回滚规则。
- 用户数据目录、已迁移数据库路径、任务、设置、凭据和登录状态保持原值；修复不重置应用配置。

### 10.6 UI 与执行序列验证门槛

先做最小技术验证，再实现完整界面：必须用编译出的单个 MSI 证明「首次可选目录、双击同一 MSI 自动维护、健康不重装、删除文件可恢复、同大小损坏文件可恢复」五件事。

实施时明确安排产品识别、路径解析、扫描、属性设置和 CostFinalize/ExecuteAction 的先后关系；REINSTALL 与 REINSTALLMODE 必须在功能/组件动作计算生效前设置。UISequence 与 ExecuteSequence 共享同一逻辑和已验证的结果传递，/qn 缺少 UI 序列时仍可维护；/x 卸载及 MajorUpgrade 的旧产品移除不得误触发扫描修复。维护健康分支在写文件的执行阶段之前结束。

需要同时测试 `/i <同一 MSI>`、双击 UI、`/qn`、显式 `/f`、`/x` 与旧版本升级；显式强制 `/f` 保留原有 MSI 修复语义，不让健康分支吃掉调用者明确要求的强制修复。条件与调度以真实 MSI 日志和文件写入结果为证据，不能只验证 XML 中出现了属性。

如果技术验证暴露 UI/执行序列冲突，应在同一个安装器交付中修正序列设计；不得用应用内维护按钮或要求用户另开命令行替代双击 MSI 的需求。

### 10.8 已有安装兼容与验收矩阵

旧安装的 UpgradeCode、per-user 范围及既有组件 GUID 保持一致。首次升级到支持本方案的新版本时在原位置升级，并由新版本补齐安装路径元数据；以后同版本维护读取该位置。旧版 MSI 本身不会因新版本发布获得新维护 UI，用户需先使用新包升级。不同版本不借本版清单校验旧版文件。

所有安装/破坏实验在干净 Windows 用户或可回滚 VM 内完成；绝不删除当前真实安装文件作为测试。用户数据验收放置测试任务、设置、虚构凭据和哨兵文件，并核对操作前后内容。

| 场景 | 必须满足的结果 |
| --- | --- |
| 首次默认位置 / 中文空格自定义路径 | 安装成功；ARP、产品路径元数据与两类快捷方式一致；可启动并保存任务 |
| 取消位置选择 / 无权限 / 卷根 / UNC / 数据目录 / 无登记目录冲突 | 安装前明确处理，不写用户数据，不留下半安装 |
| 自定义位置已安装，完整状态双击同一 MSI | 自动扫描，显示无需修复；文件字节与修改时间、快捷方式、应用运行状态均保持；不重复创建产品登记 |
| 删除 EXE、运行时 DLL、业务 DLL、语言资源或整个安装目录 | 主程序不可运行时 MSI 仍能扫描并离线恢复，复检通过 |
| 截断文件、改写同大小字节、有版本号 DLL 保持版本但内容损坏 | 检测到哈希不符，实际替换，修复后与包内 SHA-256 一致 |
| 删除或改坏桌面/开始菜单快捷方式 | 恢复到原登记安装路径，工作目录正确 |
| 无关文件、任务数据库、配置、凭据、已迁移数据库 | 维护前后保持，扫描与修复只作用于产品拥有的程序载荷/快捷方式/必要登记 |
| 程序正在运行 | 健康不关闭；需修复时先提示保存关闭，取消则停止；进程或其他程序锁定文件时返回清晰状态 |
| 扫描取消、文件不可读、安装盘离线、安装源不可用 | 不误报健康或成功；可诊断且不另装到默认目录 |
| MSI 修复事务中失败与失败回滚 | 记录日志，遵循事务恢复规则；失败后不展示成功，用户数据不变 |
| 0.17.2 升级至新版本 | 使用原默认路径升级，新增路径登记正确；用户数据保留；随后同版本双击进入维护 |
| 已有新式自定义目录，再升级到更高版本 | 原位升级，不落回默认位置；升级后同版本维护仍修复该目录 |
| 旧 MSI / 新 MSI / 不同产品身份的同版本包 | 旧包行为如实说明；新包正确维护自己的版本；身份冲突不产生双份登记或误修复 |
| 双击、`/i /qn`、显式 `/f`、`/x`、降级 | 分流准确；静默可用，强制修复不被跳过，卸载不触发维护，降级拒绝 |
| ICE 与包结构检查 | 不新增不明全局抑制；负载、清单和组件映射一致；两条打包链产物行为一致 |

交付记录逐项区分静态包检查、自动化逻辑测试与真实 Windows Installer 执行结果。安装成功截图不能代替损坏修复实验；构建成功不能代替 MSI UI 维护验收。版本号在实施时按最新正式版分配，源码、测试、文案、迁移兼容说明、Release 与 MSI 一次交付。
