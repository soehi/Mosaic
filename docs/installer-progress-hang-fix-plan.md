# 安装器停在“正在处理，请稍候”修复方案

日期：2026-11-20。状态：已全部完成（2026-11-21）——源码修复、静态回归（旧 0.17.5 包失败、新 0.17.6 包通过）、版本与发布元数据、完整界面实机验收矩阵（隔离账户 MosaicQa0176，8 场景全部通过，含 0.17.5 卡死复现与 0.17.6 修复验证）；实机验收中追加发现并修复三个包缺陷（UI 自定义路径资源子目录落位、成功收尾误报取消、REINSTALL 跨会话传递），详见 docs/implementation-status.md 0.17.6 实机验收章节与 docs/evidence/0.17.6/ui-matrix/。

## 问题与职责

用户运行安装包后一直停在“正在处理，请稍候...”页面，进度条和当前操作为空。截图内容与 `ProgressDlg` 一致。

电脑客户端完成一个完整交付单元：本方案、安装器实现、回归检查、实机验收、发布说明与实施记录。本会话只定位、规划与交接，不修改产品实现，不操作用户当前安装会话。

## 根因位置与证据

以下位置对应当前 0.17.5 源码。

1. **模态进度页阻塞安装执行。** `build/installer/Dialogs.wxs:126` 的 `ProgressDlg` 没有声明非模态；`build/installer/Package.wxs:75` 在 UI 序列 1290 显示它。实际发布 MSI 中，`Dialog` 表的 `ProgressDlg.Attributes=3`，包含 `msidbDialogAttributesModal` 位（2）；`InstallUISequence` 的 `ExecuteAction` 位于 1300。界面序列等待模态进度页结束，无法进入真正执行安装的动作；页面又只有退出按钮，正常等待不会推进。这是已确认的包结构缺陷，仍须完整 UI 日志验证用户路径。
2. **显示没有订阅引擎事件。** `Dialogs.wxs:128` 的当前操作只是属性文字 `[ActionText]`，`:131` 的进度条没有事件订阅。发布 MSI 的 `_Tables` 中不存在 `EventMapping`。解除阻塞后仍需接通真实进度和操作文本。
3. **取消必须随非模态化验证。** `Dialogs.wxs:132-134` 直接发布 `EndDialog Exit`，发布 MSI 的 `ControlEvent` 也如此。改成非模态后，需验证取消通知安装引擎并完成回滚，不能仅关闭窗口或留下后台安装。
4. **旧检查遗漏此类缺陷。** `build/test-package-maintenance.ps1:126-139` 检查进度页序号，`:200-201` 检查摘要，但未检查模态位和事件映射。静默安装不经过完整 UI 序列，不能覆盖该问题。

只读核验对象：`artifacts/installer/Mosaic-0.17.5-win-x64.msi`，52,466,396 字节，SHA-256 `f8f23394eaf0b82f36454c3c83a3c89d4888ccc3c3d177c4321b82c3c405b433`。通过 Windows Installer 数据库 API 只读查询，未执行安装或更改产品登记。

## 复现与定位顺序

在受控隔离 Windows 环境中，先保存旧 MSI 完整 UI 复现的详细日志与截图。使用默认完整界面或 `/qf`，日志启用 `/L*V!`；首次安装及确有损坏的同版本维护都要进入进度页。健康维护提前结束不能代替复现。正常取消阻塞复现，记录取消结果；不得杀掉全部 msiexec。

按证据强弱验证三个预测：

- 模态阻塞：旧版日志显示进度页后没有开始 `ExecuteAction`；仅修正非模态属性后，同一路径能进入执行阶段。
- 显示订阅缺失：日志已执行但 UI 没有变化；接入引擎事件后操作文字与进度随动作更新。
- 其他等待：若日志已开始执行，才继续定位最后一个动作、文件占用、其他安装会话或原生扫描耗时。不要用假进度、盲目重试、固定超时掩盖等待原因。

本计划不把只读表检查当作实机复现；电脑客户端必须补齐修复前失败、修复后通过的反馈闭环。

## 实施要求与预期改动位置

- `build/installer/Dialogs.wxs`：将 `ProgressDlg` 按 WiX 4 / Windows Installer 支持的方式设为非模态（优先 `Modeless="yes"`），确保返回 UI 序列后执行 `ExecuteAction`；进度条订阅 `SetProgress` 到 `Progress`，当前操作订阅 `ActionText` 到 `Text`，需要时另设 `ActionData` 控件。以实际编译的 MSI 表为准，不能只检查源码文字。
- 同文件：采用标准取消确认和安装引擎取消语义；核对执行期间、确认取消、继续安装及回滚期间的行为。成功、失败、取消、待重启页面和进度窗口生命周期须一致，不得多弹窗口或误报成功。
- `build/installer/Package.wxs`：核对进度显示、`ExecuteAction`、复检和结果页的顺序与条件。保持同版本自动扫描、健康提前结束、损坏自动修复、显式修复参数及静默入口语义；不要为了让窗口关闭而跳过安装或复检。
- `build/test-package-maintenance.ps1`：对编译 MSI 增加结构回归：进度页非模态且可见、位于实际存在的 `ExecuteAction` 前、`EventMapping` 的进度/文本订阅正确、取消事件符合最终设计。旧 MSI 必须在对应断言失败，新 MSI 通过；这只是静态回归，还须完整 UI 实测。
- 交互验收脚本：由电脑客户端选择现有测试入口或新增有明确用途的脚本，驱动真实 Windows Installer UI，记录动作顺序、退出码与结果。不得以 `/qn`、`/qb` 或源码关键词替代完整 UI 验收。
- `docs/implementation-status.md`、`docs/installer-location-plan.md`、对应版本发布说明：写明根因位置、每个实际改动文件/类型/行号、修复前后证据、兼容性和未验证项。版本及发布元数据随最终补丁统一更新。

## 验收门槛

| 场景 | 必须取得的结果 |
|---|---|
| 完整 UI 首次安装，默认及自定义含空格/中文路径 | 无需点击进度页即可执行；日志到达 ExecuteAction、InstallInitialize、InstallFiles、InstallFinalize；最终完成，路径/ARP/快捷方式正确，应用可启动 |
| 同版本损坏维护 | 只破坏隔离安装；缺 EXE 或同尺寸损坏 DLL 后自动扫描并修复；显示扫描摘要与实际执行进度，复检哈希恢复 |
| 同版本健康维护 | 健康提前结束，不进入写入阶段，文件哈希与时间、用户数据不变；记录交互退出码，不混称成功或失败 |
| 从 0.17.5 升级 | 使用旧包在隔离环境准备，保留自定义位置和数据，不在默认路径另装；完整 UI 可完成 |
| 取消确认/继续与实际取消 | 初始页面及执行期间分别验证；“继续”不终止安装，“取消”正常结束/回滚并返回取消结果，无后台会话残留 |
| 占用或失败 | 有明确提示与结果，进度不能永久空白；失败不得出现成功页，回滚和文件状态与日志一致 |
| 静默兼容 | 原有静默安装/修复、健康扫描、1603、卸载及原位升级检查不退化 |

不要以固定秒数断言所有安装必须完成；用日志动作进入/退出、UI 可响应性和具体等待原因判断。未触发的 3010 分支继续标为未实测，不制造验收记录。
