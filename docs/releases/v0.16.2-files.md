# Mosaic 0.16.2 交付文件清单

本版本只修复 0.16.0/0.16.1 从 ≤0.15.3 升级后无法启动的装配缺陷，其余内容与 0.16.1 相同。不改 `server/`、`mobile/`。

## 根因位置

- `src/Mosaic.Desktop/AppConfiguration.cs` `ApplyAuthSyncMigration`（0.16.0 版 :207-234）：`auth-sync-v1` 迁移为既有安装注册了 auth/sync 五条新绑定，但没有为同一提交（d0ccccd）新增的 `tasks.transfer-repository@1`（`TasksSqliteModule` Provides）与 `tasks.transfer@1`（`TasksModule` Provides）写入绑定；仓库内 `src/Mosaic.Desktop/appsettings.json` 的顶层 `providers` 表同样缺这两条。
- 触发条件与出错原因：`src/Mosaic.Kernel/ModuleGraph.cs` `ModuleGraph.Resolve`（:20-21）要求每个模块 Provides 的每个能力在 providers 表中有指向该模块的绑定；从 ≤0.15.3 升级的既有安装（providers 只有 14 条、无 transfer 两条）在启动解析时抛 `InvalidOperationException("Provider binding is missing or incompatible: tasks.transfer-repository@1")`，被 `HostConfigurationValidator.Validate` 捕获后转为启动失败弹窗。0.16.0 已携带该缺陷（全新安装的仓库 appsettings.json 也缺绑定），但 0.16.0/0.16.1 发布时桌面 Smoke 未重跑、实机安装未验证，故未暴露。

## 改动位置

- `src/Mosaic.Desktop/AppConfiguration.cs` `ApplyAuthSyncMigration`：迁移补 `providers.TryAdd("tasks.transfer-repository@1", "tasks-sqlite")` 与 `providers.TryAdd("tasks.transfer@1", "tasks-core")`，并注明缺陷成因。已应用过 `auth-sync-v1` 的安装（0.16.0/0.16.1 期间成功启动过、或全新安装）不重复执行迁移——这些安装本就绑定完整，`TryAdd` 幂等，不需要二次迁移。
- `src/Mosaic.Desktop/appsettings.json`：顶层 `providers` 补 `"tasks.transfer-repository@1": "tasks-sqlite"` 与 `"tasks.transfer@1": "tasks-core"`，全新安装直接绑定完整。
- `tests/Mosaic.Desktop.SmokeTests/DesktopTests.cs`：新增 `Auth_sync_migration_binds_the_task_transfer_capabilities`（4 个场景：top-level 与 host.modules/host.providers 覆盖组合）——用 0.15.3 形状配置（11 模块、14 绑定、无 auth-sync-v1 标记）启动真实进程，断言迁移写回 `tasks.transfer-repository@1=tasks-sqlite`、`tasks.transfer@1=tasks-core`、`auth.transport@1=auth-http`、`sync.transport@1=sync-http`，`.pre-migration` 保留原配置，且迁移后进程保持运行（此前 `ModuleGraph.Resolve` 会拒绝该配置）。
- `Directory.Build.props`、`build/installer/Mosaic.Installer.wixproj`：版本 0.16.2。
- `docs/releases/v0.16.2.md`、`docs/releases/v0.16.2-files.md`、`docs/implementation-status.md`、`README.md`、`build/release-content.json`、`build/release-manifest.json`、`build/published-release-index.json`（第 28 条，`previousReleaseId=mosaic-0.16.1`）：版本说明与实施记录。

## 迁移验收项（对已有安装的影响）

- 升级路径 0.15.3→0.16.2：`ApplyAuthSyncMigration` 在启动时自动补四条绑定（transfer 两条 + auth/sync 五条中的其余三条）并标记 `auth-sync-v1`，写入 `.pre-migration` 备份；用户无需手动修改 `%LOCALAPPDATA%\Mosaic\Config\appsettings.json`。
- 升级路径 0.16.0/0.16.1→0.16.2：此前从未成功启动的安装（迁移标记未写入）走同一迁移路径自动修复；已成功启动的安装迁移标记已存在，配置不变。
- 全新安装：仓库 appsettings.json 已含全部绑定，无迁移执行。
- 若用户以 `host.providers` 设置覆盖（`settings.host.providers`），迁移同步补写覆盖层，行为与顶层一致。

## 未改动

- `server/`、`mobile/`、0.16.1 的全部功能代码（契约、传输、服务、账户页 UI、测试）。
- 数据库表结构、既有设置键、导航契约。
