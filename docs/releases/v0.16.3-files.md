# Mosaic 0.16.3 交付文件清单

本版本让安装包自带配置修复功能：每次启动自动合并内置模块的默认能力绑定，彻底消除「新增能力缺 provider 绑定导致升级后无法启动」这一整类缺陷。不改 `server/`、`mobile/`。

## 根因位置

- `src/Mosaic.Desktop/AppConfiguration.cs` `Load`（0.16.2 版）：读取 appsettings.json 的 `modules`/`providers` 后直接交给装配校验，没有与内置默认绑定合并。模块升级新增能力时（例如 0.16.0 新增的 `tasks.transfer-repository@1`，`TasksSqliteModule` Provides），既有安装的旧配置里没有这条绑定，除非每次都恰好写了补绑定的迁移，否则 `src/Mosaic.Kernel/ModuleGraph.cs` `ModuleGraph.Resolve`（:20-21）在启动时抛 `InvalidOperationException("Provider binding is missing or incompatible: …")`，经 `HostConfigurationValidator.Validate` 转为启动失败弹窗。0.16.2 的 `ApplyAuthSyncMigration` 只修复了这一次缺失的两条绑定，机制上仍依赖「每次新增能力都记得写迁移」。

## 改动位置

- `src/Mosaic.Desktop/AppConfiguration.cs`：
  - `Load`：在首次 `ValidateCoreConfiguration` 之前调用新增的 `RepairProviderBindings`，每次启动执行、不受迁移标记限制。
  - 新增 `RepairProviderBindings`：按生效层（`settings.host.modules`/`settings.host.providers` 覆盖优先，否则顶层）读取模块与绑定，对每个**已启用且在内置目录中**的模块，用其 manifest 声明的 `Provides` 以 `TryAdd` 语义补齐缺失绑定——已存在的绑定（用户显式配置）一律保留；未知模块 id 交给既有声明校验报错，不产生孤儿绑定。有任一覆盖层时合并结果写回 `settings.host.providers`，顶层保持原样；无覆盖层时写回顶层。无缺失时不改配置对象，`Load` 不写盘；有补齐时走既有 `WriteConfiguration` 路径，自动写 `.pre-migration` 备份。MSI Repair/重装不触碰 `%LOCALAPPDATA%\Mosaic\Config`，修复/重装后的首次启动即完成补齐，无需改 WiX。
  - 边界说明：新模块的启用仍由迁移负责（自愈只补已启用模块的能力绑定，不会静默启用网络等模块）。
- `tests/Mosaic.Desktop.SmokeTests/DesktopTests.cs`：
  - 新增 `Startup_repairs_capability_bindings_missing_from_an_upgraded_configuration`（4 场景：top-level 与 host.modules/host.providers 覆盖组合）：构造全部迁移已应用、但缺 `tasks.transfer-repository@1`/`tasks.transfer@1`/`sync.api@1` 的配置（证明补齐来自自愈而非迁移），启动真实进程，断言三条绑定被写回正确生效层、`.pre-migration` 备份等于启动前原文、进程修复后保持运行。
  - 新增 `Healthy_configuration_keeps_its_bindings_and_file_untouched`：健康配置进程内 `AppConfiguration.Load` 后文件内容逐字节不变、无 `.pre-migration`（自愈幂等、不乱写盘）。
  - 新增 `Repair_preserves_explicit_bindings_and_skips_disabled_modules`：断言显式绑定（`floating.repository@1=floating-windows-sqlite`）被保留、`tasks.changes@1` 被补齐，被禁用模块的能力（`auth.transport@1`、`sync.api@1`）不产生孤儿绑定。
  - 更新 `Configuration_presence_migration_is_validated_persisted_and_one_time` 的 `already-migrated-disabled` 场景：自愈现在会为该配置补 `desktop.presence@1` 绑定（能力由已启用的 tasks-ui 提供、被禁用的 desktop-presence 模块不会被启用、迁移标记不变），断言改为「只发生自愈补齐、不发生迁移」。
- `Directory.Build.props`、`build/installer/Mosaic.Installer.wixproj`：版本 0.16.3。
- `docs/releases/v0.16.3.md`、`docs/releases/v0.16.3-files.md`、`docs/implementation-status.md`、`README.md`、`build/release-content.json`、`build/release-manifest.json`、`build/published-release-index.json`（第 29 条，`previousReleaseId=mosaic-0.16.2`）：版本说明与实施记录。

## 安装/修复验收项（对已有安装的影响）

- 模拟旧版 appsettings.json（缺新增绑定）升级启动：自动补齐缺失绑定并写回配置（带 `.pre-migration` 备份），进程成功启动——由 `Startup_repairs_capability_bindings_missing_from_an_upgraded_configuration` 4 场景覆盖。
- 用户自定义绑定不被覆盖：`TryAdd` 语义只补缺失项，显式绑定原样保留——由 `Repair_preserves_explicit_bindings_and_skips_disabled_modules` 覆盖。
- MSI Repair/重装路径：安装器不写配置（`build/installer/Package.wxs` 无配置 CustomAction），配置目录在 `%LOCALAPPDATA%\Mosaic\Config`，Repair/重装后首次启动即由启动自愈完成补齐，无需改安装包逻辑。
- 0.16.2→0.16.3：无配置形状变化，升级无感知；此后任何版本新增能力时，旧安装升级首次启动自动补绑定。
