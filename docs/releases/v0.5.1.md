# Mosaic 0.5.1

Mosaic 0.5.1 是旧配置升级修复版。功能与模块边界沿用 0.5.0；本次只补齐 Presence 配置迁移的正确性、一次性和验收。

## 修复

- 根因位置：`src/Mosaic.Desktop/AppConfiguration.cs` 的 `AppConfiguration.Load` 在完成完整校验前直接修改配置并写回，而且没有持久化“已经迁移”状态。第一版 0.5.1 又在迁移前解析旧依赖图，旧 `tasks-ui` 配置因尚无 `presence.tasks-view@1` 先被拒绝，迁移没有机会执行，表现为启动失败或立即退出。仅存在 `settings.host.modules` 或 `settings.host.providers` 覆盖时，模块和 provider 还可能写入不同配置层，形成不完整的生效配置。
- 改动位置：`AppConfiguration.cs` 增加顶层 `appliedMigrations`、先校验后迁移、按实际生效层迁移和原子写回；`HostConfigurationValidator.cs` 成为顶层配置与宿主覆盖共用的模块/provider 校验入口；`HostSettingSource.cs` 改走同一校验入口；`tests/Mosaic.Desktop.SmokeTests/DesktopTests.cs` 增加 4 个隔离黑盒迁移场景；`src/Mosaic.Desktop/appsettings.json` 为新默认配置写入迁移标记。

## 迁移行为

- 旧版生效配置包含 `tasks-ui` 时，首次启动补入 `desktop-presence`、`presence.tasks-view@1` 和 `desktop.presence@1`。
- 迁移覆盖顶层 `modules/providers` 和设置页保存的 `settings.host.modules/providers`，只修改实际生效的配置层。
- 原配置只在校验通过后写回，并保留为 `Config/appsettings.json.pre-migration`。
- 成功后写入 `desktop-presence-v1`。以后主动禁用 Presence 不会被重新启用。
- 非法旧配置保持原样，不产生迁移备份或半迁移文件。
