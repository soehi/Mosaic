# Mosaic 手机端 0.3.5

Android 包名 `app.mosaic.tasks`，`versionCode=10`，支持 Android 8.0（API 26）及以上。Windows 配对入口和服务端是本次源码交付的一部分。客户端 APK 当前用于本地验收。

## 用户可见改动

- 小组件采用 M3.5 的暖色浅深主题。4×1 使用单行视口，4×2 使用双行视口，列表保留后续任务供原生滚动。右侧拼片标记只在足够宽的双行布局且字体缩放不超过 1.15 时显示。
- 长按系统编辑仍可切换未完成、已完成、已归档和全部。完成圆圈是唯一的任务写入入口。已完成和归档任务保持只读，服务端确认后才更新任务状态。
- Windows「账户与备份 → 下载手机组件」提供五分钟二维码。下载安装后重新扫码打开 Android 连接页，在桌面输入手机显示的六位配对码并批准。手机使用同一服务器、同一账户建立会话，并开始读取备份和增量。缺发布配置或连接旧服务端时，配对窗口显示不可用。原「下载备份」入口独立保留。

## 根因与改动位置

- 0.3.4 的 `TaskWidgetService.OnDataSetChanged` 把适配器截断到可见行数，且固定高度的 XML 没有应用程序算出的行高。0.3.5 由 `WidgetViewport.ForHost`、`WidgetRenderer.BuildViews` 和 `TaskWidgetService.LoadRows` 配合调整视口、行高并提供完整分组列表。
- 旧 Android `AndroidServerConfigProvider` 只读私有配置。新安装缺少以桌面账户写入服务器配置和加密令牌的入口。0.3.5 增加 `MobilePairingWindow`、`MobilePairingEndpoints.MapMobilePairing`、`MobilePairingService` 和 `PairingActivity`。`AuthService.GetAccessTokenAsync` 支持应用重启后按需兑换已恢复的刷新令牌。
- 调试构建原用 `TestSeedReceiver`、`TestSeedStore` 和 `MosaicWidgetTestSeed` 在运行时提供示例任务。0.3.5 移除这条路径，`WidgetSnapshotStore.RemoveRetiredFixture` 清理带旧测试偏好标记的历史快照。
- 详细文件位置、验收依据和兼容矩阵见 [实施记录](../implementation-status.md)。

## 安装和迁移

- 证书相同的 0.3.4 安装可按 Android 的版本规则覆盖升级。同包名、不同签名会被 Android 拒绝。0.3.5 继续使用现有私有配置、Keystore 和投影目录，保留分组偏好。旧测试构建升级时，仅在存在专用测试偏好的情况下清理已知的六个示例 ID。重新配对会先清空上一账户的展示快照，新账户继续按服务器与用户 ID 打开各自的投影。
- 服务端启动时事务化执行 `Schema.Migration4`。v2 数据库补版本 4，已有附件版本 3 的数据库保留该记录和附件。维护窗口内应在升级前取得一致的 SQLite 备份，并保存当前主密钥配置。需要退回最高迁移号为 2 或 3 的服务端时，停服后恢复升级前的备份和对应配置。恢复备份会回退备份之后发生的服务端写入。
- Android 回装 `versionCode=9` 需卸载 0.3.5，再安装旧 APK 并重建小组件。卸载会删除当前客户端的本地会话、分组和投影。服务端任务仍保存在服务器。

## 正式入口前置条件

1. 使用正式证书签名 APK。以 `apksigner verify --print-certs` 核对签名，以 `aapt2 dump badging` 核对包名和版本，以 `Get-FileHash -Algorithm SHA256` 核对内容摘要。
2. 将正式 APK 和清单放在服务端只读发布目录。清单字段为 `package`（`app.mosaic.tasks`）、`apk`（路径，可相对清单）、`sha256`（APK 的 64 位十六进制摘要）和 `certificateSha256`（签名证书的 64 位十六进制摘要）。`MOSAIC_MOBILE_RELEASE_MANIFEST` 指向清单。服务端核对清单结构和 APK 内容哈希，证书字段由发布方从已验签 APK 提取。
3. 将 `MOSAIC_PUBLIC_URL` 配置为最终根 HTTPS 地址，默认端口 443。Android 构建的 `MosaicMobileAppLinkHost` 必须与该域名一致。该域名直接提供 `/.well-known/assetlinks.json`，由 Android 校验包名与签名关联。TLS 在反向代理终止时，服务端须通过受信代理识别原始 HTTPS。缺配置时配对 API 返回 `mobile.unavailable`。
4. 用独立测试账户和受信测试证书完成设备验收。检查同账号首轮同步、4×1 和 4×2 首屏分别一行和两行、可滚到第 3 和第 4 条、长按切组、只读限制、完成确认和覆盖升级。浅色、深色及大字体分别留存设备截图。
