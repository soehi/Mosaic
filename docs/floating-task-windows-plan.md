## 1. 已确认效果与实现默认规则

用户已确认：

- 从任务速览拖出任务，形成独立置顶小窗，可同时悬浮多个任务。
- 默认紧凑显示标题和完成状态；点击展开备注与时间，小窗可调整大小。
- 可以查看、选择和复制内容，标记完成或恢复未完成。
- 完全退出后，下次启动自动恢复上次未关闭小窗的位置与大小。

其余采用本计划默认规则：同一工作空间同一任务只保留一个小窗，再拖出则定位已有窗；关闭速览、隐藏或最小化主窗不关闭小窗；小窗“×”只关闭展示，不删除任务。真正退出 Mosaic 关闭所有窗口，但保留未被用户单独关闭的恢复记录。不同数据目录互相隔离。

小窗默认置于其他普通应用窗口上方，不承诺覆盖系统安全桌面、独占全屏或系统自身窗口；不强制抢占焦点。不在任务栏增加每个小窗的独立图标。默认允许通过置顶按钮取消该小窗置顶，并保留该窗选择。

完成任务后小窗继续存在，允许恢复未完成。标题和备注保持只读，本期不加入编辑、删除、重排任务、吸附布局或桌面穿透。

## 2. 窗口外观与操作

### 2.1 紧凑 / 展开

```text
紧凑                              展开
┌──────────────────────────┐      ┌──────────────────────────┐
│ 拖动区             置顶 × │      │ 拖动区             置顶 × │
│ ○ 任务标题             ▾ │      │ ✓ 任务标题             ▴ │
└──────────────────────────┘      │ 备注全文，可选择复制     │
                                  │ 正文超长时在这里滚动     │
                                  │ 创建时间 / 更新时间      │
                                  └──────────────────────────┘
```

- 默认紧凑宽 320 DIP、高度随标题自然测量，目标约 88 DIP；标题最多两行，工具提示与读屏提供全文。支持调整宽度，紧凑高度随内容变化。
- 展开初始约 320×360 DIP，用户可调整宽高；长备注仅正文滚动，标题栏、状态按钮和收起入口保持可见。
- 保存展开/收起状态，并分别记住紧凑宽度、展开宽高，展开/收起不会覆盖另一种尺寸。重启按关闭程序前的模式恢复。
- 标题栏或专用空白拖动区用于移动窗口。紧凑内容或展开箭头触发展开；展开后用箭头收起，不让选择备注文字误触收起。
- 完成状态使用独立 ToggleButton，关闭和置顶使用各自 Button；这些控件的点击不冒泡成展开或拖动。
- 使用 Mosaic 主题资源、矢量状态图形、可见焦点与状态文字；已完成状态仍清楚可辨。长标题、空备注、中英文及高对比度均有明确布局。
- 默认有 1 DIP 边线、约 12 DIP 圆角；每个交互控件提供可访问名称。键盘可展开、收起、切换状态、关闭；Esc 优先关闭菜单，其次收起详情，不以 Esc 直接退出程序。
- 小窗不使用速览的鼠标离开自动收起计时。鼠标离开后保持显示，复制和滚动不中断。

### 2.2 关闭与错误反馈

- “×”成功持久化关闭状态后销毁该小窗，不弹“删除任务”确认。保存失败时留窗显示可重试反馈，避免用户认为关掉后下次又出现。
- 任务查询失败时显示错误与重试，保留移动、关闭和恢复主窗口入口；不把网络/存储异常当成任务已删除。
- 已确认任务删除时，当前小窗显示“任务已删除”，禁止状态操作，可由用户关闭；同时撤销下次恢复资格。恢复时确认不存在的任务跳过并清理其恢复记录。
- 切换完成状态提交期间只禁用该任务的状态按钮；成功后更新文字与图形。失败保持已确认的旧值，显示错误，不假装保存成功。

## 3. 拖出手势与窗口创建

1. 在速览任务按钮按下时记录任务引用与起始位置；超过系统水平/垂直拖动距离才进入拖动。阈值以内松开仍走现有“面板内查看详情”。
2. 拖动开始后取消这次按钮 Click；显示轻量预览，并暂停速览自动收起和外部点击收起。保持鼠标捕获，直到释放、Esc 或捕获丢失。
3. 松手点在速览外的可用屏幕工作区内才申请创建小窗；松手仍在速览内、Esc、捕获丢失或目标无效均取消，零窗口、零任务写入，也不补发详情点击。
4. 不对其他应用或桌面发送文件/文本拖放，不调用外部应用的 Drop。此手势只在 Mosaic 内请求创建独立展示窗口。
5. 创建点以释放指针和抓取偏移计算，窗口夹取到释放点所在显示器的工作区；从速览拖出后原任务仍留在列表，不创建第二条任务记录。
6. 同一任务的并发拖出申请合并，同键处于 Opening 或 Open 时均不得新建第二窗；返回 Created / ActivatedExisting / Rejected 等明确结果。
7. 新开窗口的任务身份、窗口初始状态须成功保存后才宣告拖出成功；失败回收新视图和窗口，并在原速览反馈。成功后释放捕获，再恢复原速览的收起规则。
8. 为无法拖动的用户提供任务按钮上下文菜单“在小窗中打开”，与拖出调用同一个公开申请；键盘入口同样去重。

## 4. 职责划分与无循环依赖装配

| 所有者 | 唯一职责 |
| --- | --- |
| Tasks Core | 任务读取、完成状态写入、版本冲突规则、提交成功后的变更通知 |
| Tasks UI | 速览任务手势、公开内容引用、任务专用紧凑/详情视图、完成按钮与错误、本地化 |
| 新 Floating Windows Core | 通用窗口身份去重、开启/关闭/恢复策略、状态合并；无 WPF 和任务业务依赖 |
| 新 Floating Windows WPF | 创建/移动/缩放/置顶窗口、DPI/工作区、焦点、窗口关闭与会话释放 |
| 新 Floating Windows Sqlite | 窗口状态表、映射、SQL 与迁移；不查任务表 |
| Storage Sqlite | 连接、队列、事务、备份与迁移执行 |
| Presence | 速览容器与拖出期间通用交互保活；不管理独立小窗，不读任务 DTO |
| Settings | 展示已激活来源的定义，保存与预览路由 |
| Desktop | 公开模块装配、启动就绪与退出排空；不维护另一份窗口记录 |

建议程序集：`Mosaic.FloatingWindows.Contracts`、`Core`、`Wpf`、`Persistence.Contracts`、`Sqlite`。纯契约/策略/持久化项目不引用 WPF。激活模块为 `floating-windows` 和 `floating-windows-sqlite`；不为每一个窗口创建一个模块。

Tasks UI 不依赖 Floating WPF。通过公开的“项目分离申请来源”注册接口接受处理器，返回可释放注册；窗口模块依赖 Tasks UI 提供的内容工厂及该申请来源能力，激活时注册自己的公开处理器。Tasks UI 只在处理器已可用时显示拖出/上下文入口；模块停止先撤销入口、等待已接受申请再释放。

因此依赖方向为：Tasks Core → Tasks UI（提供内容工厂/申请来源）→ Floating Windows；不出现 Tasks UI 与窗口模块互相 requires。宿主只传公开接口，不用全局服务定位器，不反射获取主页面对象。

浮窗中的任务专用视图仍由 Tasks UI 工厂创建。每窗独立内容会话，复用已有只读详情的呈现组件，不复用同一个 UIElement 或 TaskPeekViewModel 实例。任务 API/DTO 只出现在 Tasks UI，通用窗口管理模块只处理公开不透明内容引用及通用展示状态。

## 5. 公开申请与生命周期草案

通用契约的含义（实施时再确定最终 C# 签名）：

- `FloatingContentReference(ProviderId, ItemKey)`：稳定身份；Tasks UI 独占 TaskId 的编码/解码，窗口管理器只比较键。
- `OpenFloatingItemAsync(reference, placementHint)`：打开或定位已有窗，返回明确结果；来源为拖出、菜单和恢复均使用同一去重流程。
- `IFloatingContentFactory.Create(reference, viewOptions)`：Tasks UI 返回独立的内容会话；会话提供 View、布局通知、通用展示模式和关闭/释放，不暴露业务仓储。
- `RegisterDetachHandler(handler)`：由公开申请来源维护可释放处理器注册，未激活或正在停止时明确拒绝；禁止异步无结果事件冒充创建成功。
- `IFloatingWindowRepository`：只读恢复记录、原子保存单窗记录、设置打开/关闭状态；窗口引用及坐标为纯 DTO。
- `ITaskChangeSource`：Tasks Core 提供的公开专用提交事实通知；附 TaskId、Revision、变更类别，不传可变实体或仓储。

窗口状态：`Closed → Opening → Open → Closing → Closed`；异常可重试，不留下 Opening 永久占位。移动/缩放期间仍为 Open。启动恢复按相同路径创建，真正退出进入统一 Stopping，拒绝新开窗。

拖动保活通过通用辅助会话交互通知/租约实现；Presence 只知“交互进行中”，不识别任务或浮窗类型。取消、错误、关窗均释放租约，不能让速览永久不收起。

## 6. 内容同步与完成状态

- 打开或恢复时通过 `ITasksApi.GetAsync` 读取最新任务；设置完成通过已有 `SetCompletedAsync(Id, IsCompleted, ExpectedRevision)`，不直接修改共享 DTO 或数据库。
- Tasks Core 在事务提交成功后发布变更事实；失败不发成功通知。观察者错误不得使已提交写入变成失败，通知回调不得在锁内同步反向查询造成死锁。
- 主任务页、速览详情与浮窗内容会话订阅同一公开变更源，按 TaskId 合并刷新；窗口管理器不解释这些通知。取消订阅及迟到响应隔离沿用会话代次。
- 同一任务外部被修改/完成后，其他可见展示更新；版本冲突时重读当前任务并提示，再由用户决定是否重试，不自动覆盖别人刚保存的内容。
- 通知是刷新提示，任务 API 是权威；新会话、重新激活和重试应重读以弥补遗漏，不用后台高频轮询维持表面同步。TaskId/Revision 保护较旧响应不覆盖较新状态。
- 新能力以独立 `tasks.changes@1` 提供，保持已有任务 API 兼容；所有新旧调用方/provider 配置、边界清单与测试同批接线。

## 7. 持久化、退出与重启恢复

窗口状态属于窗口模块，不写任务备注、设置值表或 appsettings；由专属存储适配器通过公开 Storage 会话保存。

| 数据 | 保存规则 |
| --- | --- |
| ProviderId + ItemKey | 同一工作空间唯一，不持久化任务标题和备注副本 |
| IsOpen | 用户单独关闭为 false；退出程序保留尚开窗口为 true |
| DisplayMode | Compact / Expanded |
| NormalBounds | 紧凑宽度、展开宽高；尺寸以 DIP 保存，禁止保存最小化占位坐标 |
| Placement | 显示器标识、相对工作区位置及回退位置 |
| IsTopmost | 每窗置顶选择，初次来自全局默认 |
| SchemaVersion / Revision | 迁移与旧写入覆盖保护 |

保存以一次完整窗口记录为单位原子提交。拖动/缩放中合并写入，操作结束保存最终值；模式/置顶改变及时保存；退出前排空尚未写入的最终快照。设置预览引起的临时尺寸和置顶变化不得覆盖窗口的持久化偏好，放弃预览须恢复。

真正退出的窗口销毁不能走用户“×”的取消恢复逻辑：先停止新申请，收集仍开窗口的最终记录并保存，等待任务写入与窗口状态队列排空，再关闭内容会话/窗口，按依赖顺序释放模块。无法保存时给出重试或受控退出选择，不能宣告已记住布局。

启动在模块、存储与迁移就绪后恢复，不抢焦点；缺失显示器时移到当前主屏并夹取工作区，保留可操作标题栏。DPI 改变用当前转换重新计算，不把像素当 DIP。当前屏幕较小时只收缩本次实际边界，保留原偏好。

任务不存在时清理恢复资格；提供者暂不可用、数据读取失败时保留记录和诊断，不误删；下次启动或明确重试可再次恢复。恢复失败不使整个应用启动失败，也不阻塞主窗口可用。

关闭“自动恢复”只停止下次自动开窗，不抹掉布局；关闭全部窗口的明确操作会按用户单独关闭语义更新 IsOpen。降低窗口上限不强制关掉现存窗，恢复超出上限的记录保留待用户处理，不静默丢失。

## 8. 参数与可见性

拟新增“悬浮任务窗”设置分组，由已激活窗口模块唯一注册。含普通项，因此高级关闭时分组可见；高级项仅开启后显示。当前实现仍为 84 项，本表不计为已实现数量。

| ID | 默认 / 范围 | 类别 | 生效 |
| --- | --- | --- | --- |
| `floating.restoreOnStartup` | true | Normal | 保存后，下次启动 |
| `floating.defaultTopmost` | true | Normal | 新开窗默认；已有窗保留各自选择 |
| `floating.defaultCompactWidth` | 320 / 220–640 DIP | Advanced | 新开窗 |
| `floating.defaultExpandedWidth` | 320 / 220–960 DIP | Advanced | 新开窗 |
| `floating.defaultExpandedHeight` | 360 / 180–1000 DIP | Advanced | 新开窗 |
| `floating.minWidth` | 220 / 180–480 DIP | Advanced | 可逆预览，当前窗口安全夹取 |
| `floating.minExpandedHeight` | 180 / 120–480 DIP | Advanced | 可逆预览 |
| `floating.maxOpenWindows` | 8 / 1–32 | Advanced | 下一次新开/恢复申请 |
| `floating.boundsSaveDelayMilliseconds` | 300 / 50–2000 | Advanced | 后续窗口状态写入合并，退出强制排空 |

校验默认宽高不低于对应最小值；屏幕不足时安全夹取。任务内容沿用 Tasks UI/主题的可复用文字与状态样式，不复制 Presence 的弹窗参数或做第二份同名主题定义。系统拖动阈值优先沿用系统，不新增与系统竞争的魔法像素值。

与持久化或创建窗口有副作用的参数使用 PreviewMode.None，不能在切换设置时偷偷重开/关闭小窗；可逆约束预览有独立运行覆盖层。普通/高级与全页持续预览继续遵守现有设置规则。

## 9. 迁移与同步交付

- 增加 `floating-windows-sqlite` 和 `floating-windows`、提供者绑定、Task UI 的内容/申请来源能力与 Tasks 的 changes 能力。新默认配置与旧配置生效层同批接入。
- 配置升级复用现有宿主唯一校验和一次性迁移机制，modules/providers 原子更新并备份。仅具备 Tasks UI、任务/设置与 SQLite 所需能力时接入；空模块配置不新增功能或打开数据库。
- 已迁移后用户主动禁用窗口模块不会被加回；禁用后速览无失效的拖出/小窗菜单入口，已保存恢复记录保留。恢复启用后仍按公开规则恢复。
- 窗口表由新适配器拥有独立迁移流与备份，不把窗口表塞入 Tasks 的业务迁移；任务表和已有数据保留。迁移失败完整回滚，报告具体来源。
- 目标版本由实施批次统一确定，程序集/EXE/MSI、默认配置、公开 API、引用白名单、锁文件、发布清单和说明一起更新。本次全部新增/改进/修复进入“更新简要”，同版本不重复生成。

当前缺口位置：`TaskPeekView`/`TaskPeekViewModel` 只有点击详情，无拖出申请；`ICompanionViewFactory` 只创建速览会话，无单项目浮窗内容工厂；`PresenceSurface` 只管理边缘入口和一个速览弹窗；Tasks 尚无专用公开变更源，存储没有窗口恢复记录。以上缺口不得通过读取其他模块内部对象或复制主窗口解决。

## 11. 验收矩阵

- 手势：阈值内点击一次；拖出不打开速览详情；内放/Esc/捕获丢失零窗口；并发拖同任务只一窗；菜单入口同样去重；失败反馈保留源列表。
- 窗口：多个不同任务、紧凑/展开、长标题和长备注、可复制文本、完成按钮独立、不因移出自动隐藏；关闭速览/隐藏主窗后继续可用；真正退出无残留窗口/计时器/订阅。
- 同步：主列表→小窗、小窗→主列表/速览，完成/恢复/修改/删除；失败不改状态，冲突重读，旧响应不得覆盖新值；只创建展示，不复制任务。
- 恢复：正常退出/重启、用户单独关窗、异常中断后的最后已保存状态、恢复关闭/开启、上限变化、同工作空间第二实例；跨数据目录隔离。
- 屏幕：负坐标多屏、100/125/150/200% DPI、拖过不同 DPI、显示器移除、任务栏变化、工作区不足；标题栏和关闭按钮可达。
- 持久化：开窗/关窗/移动保存失败、退出排空失败、迁移回滚、记录损坏；不使用测试数据库覆盖用户库，不静默丢记录。
- 配置：顶层及 settings.host.* 单独/联合覆盖，升级标记、备份、已迁移后主动禁用，缺提供者，空模块零数据库访问；两个新模块声明和能力同步。
- 可访问性：纯键盘打开/收起/状态切换/关闭，高对比度、读屏、浅色/深色；置顶不抢焦点。

本轮仅完成规划；不执行源码构建、数据库迁移或发布。实施完成时逐项记录实际文件/方法、测试证据和未验收项，不能用 0.7.0 的历史测试证明小窗已通过。
