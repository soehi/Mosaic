## 1. 需求与已确认范围

| 编号 | 需求 | 交付结果 |
| --- | --- | --- |
| QV-01 | 任务速览更美观 | 紧凑列表、清楚的完成状态、按内容收缩的面板、轻量操作区 |
| QV-02 | 保持模块边界 | Presence 拥有窗口，Tasks UI 拥有任务内容，查询只走任务公开 API |
| US-01 | 每次更新生成一条任务 | 每个工作空间、每个成功运行的新发布版本生成一次 |
| US-02 | 标题为“更新简要” | 标题固定为 `更新简要`，版本号写入正文 |
| US-03 | 内容涵盖本次全部变化 | 列出本次更新的全部新增、改进和修复，并说明相关兼容变化 |
| US-04 | 避免再次出现版本不对齐 | 发布清单、程序版本、配置迁移、EXE/MSI 和说明同批验证 |

“每次更新”指新的已发布软件版本在该工作空间首次启动；不按启动次数、切换设置、保存任务或每次源码修改生成。首次安装或本功能首次上线、没有历史回执时，只为当前版本创建一条介绍任务，不合并整个历史；已有回执且跨过多个版本时，只生成一条当前版本的任务，正文合并尚未公告的中间版本变化；不为历史版本逐条补任务。开发调试运行不生成，正式本地发布目录与安装版采用相同规则。

用户已确认 US-03：正文列出本次更新的全部新增、改进和修复；已有回执且跨版本升级时，按下述规则合并未公告版本的变化。正文模板、发布内容源与验收统一采用这一范围。

## 3. 任务速览视觉与交互

### 3.1 布局

采用“标题 → 数量摘要 → 任务列表 → 操作”的四层结构：

```text
┌──────────────────────────────────┐
│ 任务速览                     收起 │
│ 共 3 项 · 2 项未完成              │
│                                  │
│ ○  整理本周计划           未完成 │
│ ──────────────────────────────── │
│ ✓  完成模块边界检查       已完成 │
│ ──────────────────────────────── │
│ ○  继续下一步             未完成 │
│                                  │
│ 打开主窗口 →                 ⋯  │
└──────────────────────────────────┘
```

- 保留标题“任务速览”和清晰可访问的收起按钮；移除常驻 MOSAIC 小字及说明句。数量摘要继续由 Tasks UI 渲染。
- 外框约 12 DIP 圆角，1 DIP 细边线，统一 8/12/16 DIP 的间距。延续 Mosaic 当前主题，不另造一套主题颜色。
- 默认宽度继续为 380 DIP。内容区内边距 16 DIP；任务标题默认 14 DIP，单行任务高度目标约 44–48 DIP，长标题最多两行后省略，工具提示与可访问名称提供全文。
- 用 18–20 DIP 矢量轮廓圆和勾选表达状态。未完成使用主题强调色和较重标题，已完成使用次级标题色和勾选；状态文字默认保留，不依赖颜色辨认。
- 任务行只读，不画复选框，不使用按钮式悬停和手形光标。保持 API 返回的顺序，不在速览内另写排序、分组或筛选规则。
- “打开主窗口”改成轻量按钮；“更多”菜单内明确列出“退出 Mosaic”。边缘入口原有右键恢复/退出入口保留，菜单具有文字名称、键盘路径和焦点样式。
- Esc 和离开自动收起提示默认进入工具提示；更多菜单与工具提示属于独立的 WPF 弹出窗口，需纳入同一交互区域，同时协调鼠标离开计时、外部单击检测与键盘焦点。Esc 优先关闭菜单并返回焦点，再次按下才收起面板；关闭浮层后按真实位置恢复收起判断，点击菜单不能先被误判为外部点击。

### 3.2 高度与滚动

Presence 使用通用 WPF 内容测量决定窗口实际高度，不读取任务 DTO、数量或 Tasks 内部对象：

1. 先以目标宽度测量内容的自然高度；布局不再由嵌套 ScrollViewer 把无限高度传给窗口。
2. 实际高度取自然高度、配置最大高度与当前工作区可用高度中的最小值。外框、标题和底栏计入限额。
3. 仅任务列表取得剩余高度并滚动；标题和底栏保持可见。少量任务不留固定的大片空白。
4. 加载、空、失败使用紧凑状态区。加载完成后合并一次布局更新，重新夹取工作区并保持边缘锚点，避免反复跳动。
5. 字体、主题、DPI、工作区和设置预览变化时，以通用内容 `DesiredSize` 或辅助会话布局通知触发重测；不能通过窗口自己的 `SizeChanged` 自反馈推算自然高度。合并布局更新并去重相同尺寸，关闭时撤销订阅并校验会话代次，旧会话的通知不能移动新弹窗。紧凑模式依据可用高度预算选择，不因自然高度变化来回切换。
6. `desktop.popup.fitContent=false` 时允许使用原固定高度模式；即使固定高度也必须受工作区限制。

数量超过 `desktop.popup.maxItems` 时仍明确显示“显示前 N 项，共 M 项”，通过主窗口查看其余任务。加载失败只给出说明与重试，恢复和退出继续可用。

## 4. 更新简要任务的产品行为

### 4.1 正文模板

任务初始状态为未完成，标题固定为“更新简要”。正文以普通文本写入已有任务备注，不要求任务编辑器先支持 Markdown：

```text
Mosaic <当前版本> · 更新日期 <发布日期>
适用范围：<上次已公告版本> → <当前版本>

新增功能
1. …（本次全部条目）

功能改进
1. …（本次全部条目）

问题修复与兼容变化
1. …（包含旧配置迁移与用户需要执行的操作）
```

空类别省略。有已知尚未交付功能时写清边界，不将待验收能力列为已完成。每项用户可见新增、改进和修复均需进入对应类别，兼容变化与用户需要执行的操作随相关条目说明。

任务创建成功后成为普通任务，允许编辑、完成、删除。之后重新启动或重复安装同版本不会覆盖用户编辑，也不会重建已删除的任务。正文不随设置页语言预览反复改写；本需求默认使用中文发布内容和固定中文标题。

### 4.2 触发与异常

- 读取包内已校验的发布清单。依赖模块和数据库迁移完成后，由宿主向更新模块公开入口发出一次启动就绪申请；在主任务页第一次查询前完成本次生成尝试，使新任务首次打开即可读取。
- 一次启动只尝试一次，失败不让应用启动失败，也不无限重试。失败记入诊断；下次启动使用同一个幂等键重试，不先写“已成功”标记。
- 关闭自动生成设置时不发创建请求、不推进公告记录；重新开启后在下一次启动尝试当前版本。设置预览不创建任务。
- 读取历史回执失败时，本次停止生成并记录待重试，不能把读取失败当作“没有历史记录”继续创建。
- 未启用任务能力时不创建、不开数据库、不偷偷启用模块。配置中关闭任务能力还保留必需依赖它的更新模块时，现有模块图校验应明确拒绝该配置。
- 新工作空间独立生成一次；同一数据目录从 exe、快捷方式或安装入口启动使用同一个回执。不同 `--data-root` 对应不同任务数据，分别生成属于正常行为。
- 当前版本不高于最高已公告版本时不生成，包括降级到一个从未单独生成过任务的旧版本；再次升级同版本仍不生成。比较使用语义版本及显式升级关系，不按字符串排序，版本判断由更新模块解释回执完成。

## 5. 唯一职责与公开契约

| 所有者 | 新增或调整职责 | 禁止越界 |
| --- | --- | --- |
| Presence WPF | 容器、自然高度、工作区、恢复/退出、展示选项来源 | 不理解任务 DTO、发布正文或任务回执 |
| Tasks UI | 只读任务行、数量摘要、加载/空/失败与状态表达 | 不决定驻留生命周期，不生成发布说明 |
| Presentation WPF / Contracts | 复用视觉资源、通用展示选项；必要时增加通用测量通知 | 不依赖具体任务或更新模块 |
| 新 `release-summary` 模块 | 发布清单读取、版本范围、正文编排、自动生成策略和设置来源 | 不执行 SQL、不取得 Tasks ViewModel、不自己保存“任务创建成功”副本 |
| Tasks Core | 通用幂等创建、任务校验、明确初始完成状态 | 不识别“更新简要”或软件版本规则 |
| Tasks Sqlite | 幂等回执与任务在同一事务中持久化 | 不决定更新触发或拼接发布正文 |
| Storage Sqlite | 公开队列、事务与迁移执行 | 不解释发布内容 |
| Desktop 宿主 | 发布信息输入、模块配置、启动就绪申请与旧配置迁移 | 不代替更新模块生成任务 |
| Settings | 元数据投影、校验请求、预览会话与保存 | 不在保存/预览回调中直接创建任务 |

新增能力建议：`release.summary@1`，由独立的 `Mosaic.ReleaseSummary` 模块提供；需要 `tasks.create-once@1` 和 `settings.api@1`。先做一个无 WPF 的实现程序集，只有确有外部调用方时才进一步拆独立契约程序集。

为 Tasks 增加通用 `ITaskCreateOnceApi` 和 `tasks.create-once@1` 能力，由现有 Tasks Core 提供，保留现有 `ITasksApi` 的兼容性。请求包含来源 ID、稳定业务键、标题、备注和显式初始完成状态；结果包含任务 ID、Created/AlreadyCreated 与任务是否仍存在。设置默认“新任务已完成”不能把这类明确请求的未完成状态覆盖。

幂等能力属于 Tasks；不能采用“更新模块查一次标题，再调用 CreateAsync”，也不能在 appsettings 写一个版本号来替代事务。标题相同的用户任务不参与去重。

## 6. 幂等与存储设计

任务仓储新增原子“创建一次”请求，SQLite 适配器独占新增的通用创建回执表，例如：

| 字段 | 作用 |
| --- | --- |
| SourceId + RequestKey | 联合唯一键；此调用方使用 `release-summary` + 稳定 ReleaseId |
| TaskId | 首次创建的任务 ID |
| PayloadFingerprint | 初次请求的规范化指纹，用于检查同一业务键被错误复用 |
| CreatedAtUtc | 首次事务成功时间 |

在一个存储事务内完成唯一键检查、任务写入和回执写入；并发请求由唯一约束和事务保证只有一个成功新建。事务未提交则两者都不留下；提交成功但调用方未收到结果时，重试返回原回执。

回执独立于任务存活，不跟随任务删除级联清除。任务完成、编辑、删除、卸载后保留数据、重启均不清除去重事实。只有明确重置整个工作空间数据才重新开始。`ITaskCreateOnceApi` 同时提供按 SourceId 查询成功回执的只读申请，返回业务键与任务 ID；更新模块将业务键映射到自己的发布清单，计算已公告版本范围与降级策略。Tasks 不解释版本，不另建一份跨模块版本高水位。识别历史成功记录应先于受后续用户限额变更影响的重新创建校验。

ReleaseId 是稳定发布标识，同版本重打包不变；不使用启动时间、文件修改时间、Git commit 或正文 hash 作为去重键。同一 ReleaseId 的发布正文不可被打包流程静默替换；发布内容变化应增加发布版本。指纹仅用于检测错误复用，不能决定“再生成一次”。

任务字数校验仍使用同一套规则。用户把标题限额调到不足 4 字，或备注限额不足以容纳全文时，创建明确失败并保留待尝试状态；不静默截断、不拆成多条、不自动放宽限额。包内保留完整内容并在诊断中指出限制，修正后下一次启动可重试。

## 7. 发布清单与升级对齐

增加结构化发布内容源，包含稳定 ReleaseId、版本、发布日期、可合并的历史条目，以及本次全部新增、改进、修复和相关兼容变化。保留不可删除的已发布 ReleaseId/版本索引，完整历史正文可单独组织，但正式包必须能完整编排本次适用的版本范围；旧回执无法映射或需要合并的历史条目缺失时明确待生成，不静默漏项或回退为首次安装。发布脚本从该来源生成用户可见发布说明与包内 `release-manifest.json`；测试结果、原因和修改位置可放在单独的验证区，不能把内部日志塞进任务备注。

宿主将清单通过公开输入交给新模块。清单与程序集版本不匹配、字段缺失、正文在默认任务限额下不可完整创建时，发布检查失败。正式本地发布和 MSI 必须包含同一清单；安装器不直接接触用户任务数据库。

新增 `release-summary` 要同步处理默认模块清单、provider、引用边界、公开 API 清单与旧配置升级。复用 0.5.1 已完成的“先验证生效配置、一次性迁移、原子写回和备份”流程；不得重新编写另一套宿主配置校验。迁移仅在所需任务与设置能力已启用时接入该模块，同时更新实际生效的 modules/providers，记录独立迁移 ID。已迁移后用户主动禁用，不得下次启动自动加回。

数据库回执表由 Tasks Sqlite 的版本迁移创建，复用 Storage 的迁移事务和备份。先完成迁移再尝试公告；迁移失败不得留下半条任务或半条回执。

## 8. 参数与普通/高级展示

复用现有宽度、最大高度、任务上限、筛选、状态色、触发与自动收起设置。新增候选定义如下；现有实现仍为 74 项，本表不代表已经注册或生效：

| ID | 默认 / 范围 | 类别 | 所有者与作用 |
| --- | --- | --- | --- |
| `desktop.popup.fitContent` | true / bool | Advanced | Presence；按内容收缩 |
| `desktop.popup.padding` | 16 / 8–28 DIP | Advanced | Presence；仅应用一次外层内边距，内容不得重复叠加 |
| `desktop.popup.cornerRadius` | 12 / 0–24 DIP | Advanced | Presence；外框圆角 |
| `desktop.popup.rowGap` | 0 / 0–12 DIP | Advanced | Presence 展示策略；通过通用选项交给 Tasks UI |
| `desktop.popup.rowPaddingY` | 12 / 6–20 DIP | Advanced | 同上；行垂直内边距 |
| `desktop.popup.titleFontSize` | 14 / 12–20 DIP | Advanced | 同上；任务标题字号 |
| `desktop.popup.titleMaxLines` | 2 / 1–3 | Advanced | 同上；标题最大行数 |
| `desktop.popup.showStatusText` | true / bool | Advanced | 同上；隐藏后仍保留矢量标记和无障碍状态文字 |
| `desktop.popup.showHints` | false / bool | Advanced | Presence；是否常驻显示收起提示 |
| `updates.summaryTask.enabled` | true / bool | Normal | release-summary；是否在下次启动生成更新任务 |

9 个视觉定义仍由 Presence 唯一注册，归“驻留与边缘”，纯格式选项通过扩展的通用 `CompanionViewOptions` 传递。Tasks UI 不注册第二份相同定义；禁用 Presence 后这些项全部消失。视觉值使用可逆即时预览，放弃恢复原布局。

更新开关归现有“任务”分区，由更新模块唯一注册。它有写入任务的后续副作用，使用 `SettingPreviewMode.None`、`SettingApplyMode.Restart` 和 `UserSettings` 持久化；保存只持久化并显示下次启动生效，不立即创建任务。普通/高级继续按可见定义生成分区，切换分区不提示保存，离开设置页统一确认。

字体族、主题语义键、协议名、固定任务标题与发布身份是样式/契约约定，不复制为任意可编辑字符串。实施时同步核对设置数量、名称、范围、中英文资源与默认值；不能先改数字后补实现。

## 9. 实施顺序与验收

| 步骤 | 工作 | 覆盖需求 | 验收重点 |
| --- | --- | --- | --- |
| U0 | 锁定视觉、正文范围与发布清单规范 | QV-01、US-02、US-03 | 同一份完整样例覆盖浅色/深色和少量/超量任务 |
| U1 | 任务速览 XAML、自然高度、轻量操作与选项 | QV-01、QV-02 | 只读、无大空白、仅列表滚动、菜单不误收起 |
| U2 | Tasks 通用创建一次契约、回执迁移与适配器 | US-01、QV-02 | 并发/崩溃恢复/删除后重试均只有一条 |
| U3 | 发布模块、正文、设置和启动就绪接线 | US-01、US-02、US-03 | 第一屏可看到新任务、标题准确、正文完整、失败可重试 |
| U4 | 生效配置迁移、构建发布一致性检查 | US-04 | 顶层及覆盖配置、主动禁用、EXE/快捷方式/MSI 使用同一负载 |
| U5 | 联合回归与同批交付 | 全部 | 源码/测试/迁移/文档/产物同步，记录实际验收边界 |

视觉矩阵：0/1/3/12/超上限任务、超长中英文标题；280/380/640 DIP 宽度，240/360/560 DIP 高度上限；浅色、深色、高对比度、100–200% DPI 与小工作区。检查三个任务时面板随内容收缩；大字体和长标题不盖住状态；底栏、菜单、键盘焦点和滚动可用；不出现伪复选框或只靠颜色区分状态。

专项交互断言：更多菜单作为独立弹出窗口时不会触发外部点击收起；Esc 优先关菜单、焦点正确返回；单层内边距未被重复添加；关闭后旧会话布局通知无效，窗口自然高度不会产生测量循环。

业务矩阵：新装、同版本重启、同版本重装、跨版本升级、一次跨过多个版本、降级再升级、任务改名/完成/删除、同标题用户任务、两个并发申请、事务提交前后中断、磁盘失败和限额不足。回执保存失败不能宣称已生成；回执成功后用户任务变化不得触发覆盖。

历史内容断言：回执查询失败零创建；无法识别的 ReleaseId、缺少历史条目均明确失败并保留重试；同版本不同清单被发布检查或幂等指纹校验拒绝，不覆盖已创建任务。

禁用与升级矩阵：任务/更新/Presence 分别禁用，无数据工作空间，旧配置各覆盖组合，已迁移后主动禁用；自动生成关闭时零写入，预览开关零写入；默认配置与用户有效配置一致；回执表版本迁移失败完整回滚。

发布前只做一条串行生产构建链（`-m:1`），避免重复并发构建占满本机资源。更新 `artifacts/local-run` 前通过已有应用退出流程处理运行实例和未保存内容；保留用户数据目录，不复制测试数据库覆盖它。完成后验证直接 EXE、带参数快捷方式及 MSI 负载的版本和发布清单一致。

本轮只验证规划文档的链接、结构和差异，不将以上验收矩阵写为已通过。实施后的记录必须列出实际改动文件/类型、上述原因定位的处理结果、已运行测试及尚未验收范围。
