# 设置页排版与服务器地址入口收口计划

日期：2026-11-20

状态：已由 0.17.2 实施（源码、测试、发布说明与实施记录同一提交见 `docs/implementation-status.md` 与 `docs/releases/v0.17.2.md`）。实施时的根因对照与原计划一致；离屏截图核对结果、XAML 编译插曲与未验证项记录在实施记录中。本计划面向 Windows 桌面端，由电脑客户端会话实施时将源码、回归、发布说明与实施记录作为一个完整交付单元。

## 1. 目标与范围

- 修正用户截图中维护页的重复标题、内容贴边、左右留白失衡，以及操作区域在小窗口下的可达性。
- 移除图二「账号服务器地址」在通用设置中的输入框、说明、默认值和恢复默认入口，普通与高级模式均不展示。
- 保留开始页的官方登录与自建服务器选择；已有服务器地址继续供账户流程使用。
- 沿用现有外观与配色，保持数据库迁移、配置检查、修复安装、卸载的现有执行逻辑与确认规则。

## 3. 页面布局方案

### 3.1 明确容器与页面的职责

- 设置容器保留唯一的分区标题「维护」。维护页删去第二个大标题，仅保留一行简短说明。
- 模块页面的 ContentControl 明确设置水平、垂直内容伸展，使页面获得实际可用宽高。
- 模块页面自己负责内部滚动和内边距：维护页四周使用约 20–24 DIP，底部保留至少 24 DIP；不在设置容器外再套 ScrollViewer。
- 维护页内容宽度跟随可用空间伸展，取消根部靠左的 820 DIP 限制。卡片横向填充；路径输入框按剩余空间伸缩，不写死宽度。
- 内容只保留一个垂直滚动区域，标题固定在容器头部，滚动条不盖住卡片或按钮。
- 「0 项设置」仅用于通用设置行页面，维护与账户等模块贡献页面不显示条目计数。
- 高级设置开关与恢复默认属于通用参数编辑：进入模块操作页时隐藏相关通用控件；切回参数页恢复显示。普通参数页仍保持原有预览、保存和恢复规则。
- 设置总说明按当前页面切换：参数页显示预览与保存说明，维护页显示按按钮执行的说明，避免暗示维护操作会在离开页面时统一保存。

### 3.2 维护页内容顺序

```text
维护                                    ← 设置容器唯一标题
──────────────────────────────────────
管理数据库位置、检查配置及修复或卸载应用。

[存储位置]
 当前数据库路径（可换行）       数据库大小
 新的存储文件夹
 [随可用宽度伸展的路径输入框] [选择文件夹]
 [迁移并重启]
 仅迁移数据库；完成后自动重启，默认保留原库。

[应用维护]
 安装版本 / 安装状态
 本机数据目录（可换行）
 [检查并修复]
 ────────────────────────────────────
 卸载 Mosaic
 □ 同时删除本机数据（不可撤销）
 [卸载 Mosaic]

[操作结果或错误提示，按需出现]
```

- 两张卡片纵向排列，卡片内边距约 20–22 DIP，卡片间距 16 DIP。
- 将修复与卸载区分为两组：删除数据复选框紧邻卸载按钮，避免被理解成影响修复。
- 修复入口文案可用「检查并修复」，准确表达已有健康检查流程；实施时核对本地化与命令一致性。
- 窄窗口下，选择文件夹按钮移至路径输入框下一行；操作区可换行，长路径与说明可换行，复选框文本使用可换行 TextBlock。
- 操作状态在相关操作区域附近展示，并确保键盘焦点与错误提示能够滚动进入视口。
- 不以减小字号或隐藏必要信息解决空间问题。

## 4. 移除「账号服务器地址」通用设置入口

不能直接删除 `AuthSettingsSource.ServerUrl` 的定义或持久化键：`AuthService.ActivateAsync`（`src/Modules/Auth/Mosaic.Auth.Core/Internal/AuthService.cs:49`）读取该值来恢复当前服务器，`SetServerAsync`（`:122`）经设置服务保存连接信息。直接删除会破坏登录与已有账户恢复。

实施方案：

1. 在 `SettingDefinition` 尾部添加默认开启的展示元数据，例如 `ShowInSettings = true`，区分供模块使用的设置与供用户直接编辑的设置；不更改现有枚举值和持久化键。
2. `auth.serverUrl` 标记为不在通用设置中显示。
3. SettingsViewModel 在两条初始化路径及重建行时，统一只为可展示定义生成 SettingRow；分区列表、计数、搜索（若存在）与恢复默认范围均基于这些行。
4. Settings Core 的定义注册、读取、验证、模块提交与即时应用流程保持完整，账户流程仍可经 `ISettingsApi` 保存地址。
5. 通用「恢复全部默认」不能清空已隐藏的服务器地址，也不能因此使已登录账户退出或换服。
6. 已有本地地址原样保留；不自动替换为官方地址、不清空、不触发网络请求、不清理登录凭据。
7. 如对应中英文资源键不再有引用，可一起清理；不得把账户开始页的服务器选择与提示资源误删。

本次不顺带改变 `auth.accountChoiceMade` 的业务逻辑。

## 6. 旧安装兼容与验收

本次没有数据库表结构、数据目录或服务器协议迁移。兼容逻辑是保留原定义 ID、存储值与模块读写路径，仅改变设置展示元数据；新增元数据默认 true，其他模块的设置保持原行为。所有检查使用隔离数据目录与虚构地址，不改真实用户数据库。

必须验收：

- 旧安装已有官方或自建服务器地址：升级后通用设置不再出现图二项目，重启后仍读取原地址，同源凭据恢复规则保持正常。
- 全新安装：官方登录、自建服务器、离线选择均可用，选择结果能保存并在重启后恢复。
- 普通/高级模式均不展示服务器地址行；恢复当前分区及恢复全部默认不改该隐藏地址。
- 维护页只出现一个分区标题；不出现「0 项设置」、参数预览保存说明或不适用的高级/恢复按钮。
- 切回任务、外观、存储与系统等参数页，计数、预览、保存、恢复默认与高级模式正常；跨页未保存提示保持正常。
- 在应用支持的最小窗口尺寸以及 1280×720、1920×1080 场景检查布局；如最小尺寸限制更大，记录实际限制，使用对应可达的窗口尺寸测试。
- 在 100%、125%、150%、200% Windows 缩放下检查实际 DIP 布局，至少覆盖浅色/深色与中文/英文；不出现水平滚动、按钮重叠、长路径越界或不可达的卸载区。
- 长路径、较长错误提示、未检测到 MSI 安装三种状态下，滚动到底能看到完整末尾说明并保留底部留白。
- 键盘 Tab 可到达选择文件夹、迁移、检查修复、卸载相关控件；焦点可见并可滚动到视口。
- 在隔离环境验证迁移、检查修复和卸载确认入口未被布局改动破坏；不在真实用户安装上执行卸载或数据删除验收。
