状态：2026-11-16，用户交互选择已确认，规划定稿，尚未实施。实现基线为当前 0.6.0。任务块采用按钮样式及真实点击行为，在速览面板内查看只读详情；为后续拖出成为多个独立置顶任务小窗做好准备。

## 1. 已确认的交互选择

用户已确认以下三项，作为本轮实现与后续扩展的依据：

| 选择 | 已确认方案 | 对实现的影响 |
| --- | --- | --- |
| 点击后的详情位置 | 速览面板内切换详情，可返回列表 | Tasks UI 内部导航；不恢复主窗、不先创建独立窗口 |
| 详情操作范围 | 只读标题、备注、完成状态与时间 | 只调用查询 API，不引入第二套编辑和保存流程 |
| 后续拖动含义 | 拖出速览成为置顶小窗，可同时悬浮多个任务 | 后续增加独立窗口管理模块，与速览页面生命周期分离 |

以下第 2–4 节按已确认组合展开。本次交付按钮、面板内只读详情与返回；实际拖出及多置顶窗口属于后续交付。实现默认沿用现有自动收起设置，文本选择、滚动、菜单与键盘阅读期间保持交互有效；操作结束且指针/焦点离开交互区域后按既有延迟收起，不新增第二套收起设置。

## 2. 本次实现范围

### 2.1 任务块改为按钮

- 整块采用真正的 WPF Button，保留状态图形、标题与状态短文字；增加轻背景、圆角、细边线和适度行间距，避免恢复为过高的大卡片。
- 显示 Normal、Hover、Pressed、KeyboardFocus 和 Disabled 状态；文字/图标始终符合浅色、深色和高对比度主题。
- 鼠标悬停提示“查看任务详情”；Tab 可聚焦，Enter/Space 打开对应任务，按钮可访问名称包含任务标题、状态和用途。
- 点击任务块只执行一次详情动作，点击完成标记也属于打开详情；完成标记不伪装为可切换状态的复选框。
- 行模型必须保留稳定 TaskId；相同标题的两个任务可分别查看，不能用标题或列表下标识别任务。

### 2.2 面板内只读详情

```text
列表                         详情
任务速览                     ← 返回任务列表
[ ○ 任务 A       未完成 ]     任务 A
[ ✓ 任务 B       已完成 ]     ○ 未完成
                             备注全文（可选择、复制、滚动）
                             创建时间 / 更新时间
```

- 点击后进入独立只读详情视图；完整显示标题、备注、完成状态、创建时间与更新时间。空备注显示明确空态，时间按当前语言格式展示，存储继续使用 UTC。
- 通过 `ITasksApi.GetAsync(TaskId)` 获取最新详情；列表快照可作为加载占位，不能把旧快照标成最新结果。
- 提供加载、重试和任务已删除状态；失败仍可返回。A 任务的迟到响应不能覆盖后来选择的 B 任务，返回或关闭后结果不再写入页面。
- 返回后恢复原筛选、任务顺序、滚动位置和源按钮焦点。主题/语言切换更新显示，不清空选中身份或导航历史。
- Esc 优先关闭菜单，其次从详情返回列表，再次按下才收起速览；返回只读详情不触发未保存确认。
- 详情仍受弹窗宽度、最大高度、工作区约束；正文滚动，返回入口固定，底部恢复/退出继续可用。
- 状态路径为“列表 → 详情加载 → 详情/失败/已删除 → 返回列表”。收起并重新打开速览时从列表开始并按既有规则重新查询；详情请求随旧会话取消，不在后台复活页面。恢复主窗口仍走原有公开恢复申请。
- 本次不在页面上显示尚不可用的拖动把手或“悬浮”按钮，不把“为拖出做准备”标为拖出功能已经完成。

## 4. 为后续拖出悬浮保留的设计

点击、拖动与窗口管理需要分清归属：

1. Tasks UI 拥有按钮激活与手势识别；按下记录候选，普通松开才视为点击。未来拖动超过系统阈值后进入 Dragging，同时取消这次 Click；取消拖动或在无效位置释放不创建窗口，也不补发详情点击。
2. 阈值优先使用系统水平/垂直拖动距离，不硬编码像素；处理鼠标捕获丢失、Esc、跨屏 DPI 与滚轮，避免小幅抖动误拖。此轮保留清楚的命令入口和稳定 TaskId，未来手势接入不要求重写任务块或业务接口。
3. 将来新增独立悬浮窗口模块，拥有窗口创建、移动、置顶、关闭、多窗口与工作区夹取。已确认目标为同时悬浮多个任务，置于其他普通应用窗口上方；不依附主窗口的显示或最小化。模块通过公开任务内容工厂申请独立只读会话；工厂由 Tasks UI 实现，并通过 `ITasksApi` 获取数据。
4. 跨模块传递公开内容引用/句柄，不传 Tasks ViewModel、数据库对象或正在显示的 UIElement。每个悬浮窗创建自己的视图、取消令牌和会话；关闭速览不能销毁已独立创建的悬浮窗。
5. 拖出通过公开申请返回成功或失败；失败保留源列表与可恢复反馈，不隐藏来源后留下不可访问任务。数据库中的同一 TaskId 始终是唯一权威任务，不因拖出复制任务记录。
6. 2026-11-17 的小窗计划已补齐唯一任务窗口、主窗隐藏后保留、启动恢复位置/大小、删除反馈和公开变更通知等规则；后续实现以新计划为准，不复用 Presence 的单弹窗生命周期管理独立任务小窗。

| 阶段 | 交付 | 验收 |

| D2 | 独立只读详情、查询与返回 | 标题/长备注/空备注/状态/时间、错误重试与删除反馈完整 |
| D3 | 容器导航、测量和生命周期协调 | Esc 优先级、自动收起、菜单、滚动和焦点恢复正确 |
| D4 | 回归、发布与更新任务 | 定义/代码/测试/文档/产物同步，更新简要包含本次全部变化 |

必测：A→B 快速切换、查询中返回/关窗、旧请求迟到、同名任务、已删除任务、极长中英文备注、文本复制、主题/语言切换、280/380/640 DIP、100–200% DPI、最大高度与小工作区；鼠标按下后移出、捕获丢失不误激活；键盘焦点处于正文时方向键不能被 Presence 强行夺走。

未来拖动的测试在对应阶段落实：阈值内松开点击一次，越阈值拖动不触发详情；取消零窗口；拖出成功一窗、零任务复制；关闭速览保留悬浮窗，退出应用释放全部会话。

本轮仅规划，不执行程序构建或用户数据操作。实现完成后同步默认与旧配置、发布清单、本地 EXE/MSI 和更新简要；如无配置或数据库迁移需求，明确记录无迁移项并验证旧工作空间照常可用。
